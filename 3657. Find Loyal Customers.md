# Find Loyal Customers - Multi-Language Solutions & Explanations

This document provides optimized implementations and line-by-line analyses for the **Find Loyal Customers** problem across five distinct language environments: MySQL 8.0, MS SQL Server 2019, PostgreSQL 16, Oracle SQL 11.2, and Python 3.10 (with Pandas 2.2.2).

## Core Requirements Checklist
To be considered a loyal customer, a user must satisfy three strict evaluation rules:
1. **Purchase Volume:** Made at least 3 transactions where `transaction_type = 'purchase'`.
2. **Account Longevity:** Has an active span of at least 30 days between their first and last transaction (inclusive).
3. **Refund Risk Control:** Maintains a total refund rate of strictly less than 20% across all their transactions.

---

## 1. MySQL 8.0

### Optimized Single-Pass Solution
```sql
SELECT 
    customer_id
FROM 
    customer_transactions
GROUP BY 
    customer_id
HAVING 
    SUM(CASE WHEN transaction_type = 'purchase' THEN 1 ELSE 0 END) >= 3
    AND DATEDIFF(MAX(transaction_date), MIN(transaction_date)) >= 29
    AND (SUM(CASE WHEN transaction_type = 'refund' THEN 1 ELSE 0 END) / COUNT(*)) < 0.20
ORDER BY 
    customer_id ASC;

```

### Alternative Approach (Using Window Functions & CTE)

```sql
WITH CustomerMetrics AS (
    SELECT 
        customer_id,
        transaction_type,
        transaction_date,
        COUNT(CASE WHEN transaction_type = 'purchase' THEN 1 END) OVER(PARTITION BY customer_id) as purchase_count,
        COUNT(CASE WHEN transaction_type = 'refund' THEN 1 END) OVER(PARTITION BY customer_id) as refund_count,
        COUNT(*) OVER(PARTITION BY customer_id) as total_count,
        MIN(transaction_date) OVER(PARTITION BY customer_id) as first_date,
        MAX(transaction_date) OVER(PARTITION BY customer_id) as last_date
    FROM 
        customer_transactions
)
SELECT DISTINCT
    customer_id
FROM 
    CustomerMetrics
WHERE 
    purchase_count >= 3
    AND DATEDIFF(last_date, first_date) >= 29
    AND (refund_count / total_count) < 0.20
ORDER BY 
    customer_id ASC;

```

### Line-by-Line Explanation (Optimized Solution)

* **`SELECT customer_id`**: Specifies that the final output table should only contain the unique identifier of the target customers.
* **`FROM customer_transactions`**: Sets the data origin point to the source transactions ledger.
* **`GROUP BY customer_id`**: Segregates raw records into bucketed sets grouped exclusively by each unique customer.
* **`HAVING`**: Instructs the engine to filter rows at the aggregated collection stage rather than the granular row stage.
* **`SUM(CASE WHEN transaction_type = 'purchase' THEN 1 ELSE 0 END) >= 3`**: Iterates through each record in a customer's bucket; if the type matches `'purchase'`, it increments by 1. The total aggregated sum must pass the threshold of 3.
* **`AND DATEDIFF(MAX(transaction_date), MIN(transaction_date)) >= 29`**: Finds the temporal boundary of customer activity. Because the problem demands an *inclusive* 30 days, day 1 to day 30 creates a statistical delta of 29 (e.g., `30 - 1 = 29`).
* **`AND (SUM(CASE WHEN transaction_type = 'refund' THEN 1 ELSE 0 END) / COUNT(*)) < 0.20`**: Isolates refund row frequencies and divides them by the absolute total activity record footprint (`COUNT(*)`). In MySQL, this floating division outputs accurately without structural casting.
* **`ORDER BY customer_id ASC;`**: Enforces strict ascendant organization on the output table array.

## 2. MS SQL Server 2019

### Optimized Solution

```sql
SELECT 
    customer_id
FROM 
    customer_transactions
GROUP BY 
    customer_id
HAVING 
    SUM(CASE WHEN transaction_type = 'purchase' THEN 1 ELSE 0 END) >= 3
    AND DATEDIFF(day, MIN(transaction_date), MAX(transaction_date)) >= 29
    AND (SUM(CASE WHEN transaction_type = 'refund' THEN 1.0 ELSE 0.0 END) / COUNT(*)) < 0.20
ORDER BY 
    customer_id ASC;

```

### Line-by-Line Explanation

* **`SELECT customer_id FROM customer_transactions GROUP BY customer_id`**: Gathers target keys and forms aggregate group boundaries for evaluation.
* **`HAVING SUM(CASE WHEN transaction_type = 'purchase' THEN 1 ELSE 0 END) >= 3`**: Executes an inline conditional sum over the grouped dataset to validate minimum transaction frequencies.
* **`AND DATEDIFF(day, MIN(transaction_date), MAX(transaction_date)) >= 29`**: Calculates time differences. Unlike MySQL, T-SQL requires an explicit interval indicator flag (`day`) and follows an `(interval, start_date, end_date)` architectural design pattern.
* **`AND (SUM(CASE WHEN transaction_type = 'refund' THEN 1.0 ELSE 0.0 END) / COUNT(*)) < 0.20`**: **Critical T-SQL adjustment.** SQL Server defaults to floor integer division if integers are divided by integers (e.g., `1 / 5 = 0`). Forcing `1.0` and `0.0` data literals shifts the expression evaluation context to a precise decimal data type, preserving the correctness of the `< 0.20` validation rule.
* **`ORDER BY customer_id ASC;`**: Formats final sequence outputs in ascending order.

## 3. PostgreSQL 16

### Optimized Solution

```sql
SELECT 
    customer_id
FROM 
    customer_transactions
GROUP BY 
    customer_id
HAVING 
    SUM(CASE WHEN transaction_type = 'purchase' THEN 1 ELSE 0 END) >= 3
    AND (MAX(transaction_date) - MIN(transaction_date)) >= 29
    AND (SUM(CASE WHEN transaction_type = 'refund' THEN 1.0 ELSE 0.0 END) / COUNT(*)) < 0.20
ORDER BY 
    customer_id ASC;

```

### Alternative Approach (Using FILTER Syntax)

```sql
SELECT 
    customer_id
FROM 
    customer_transactions
GROUP BY 
    customer_id
HAVING 
    COUNT(*) FILTER (WHERE transaction_type = 'purchase') >= 3
    AND (MAX(transaction_date) - MIN(transaction_date)) >= 29
    AND (COUNT(*) FILTER (WHERE transaction_type = 'refund')::NUMERIC / COUNT(*)) < 0.20
ORDER BY 
    customer_id ASC;

```

### Line-by-Line Explanation (Optimized Solution)

* **`SUM(CASE WHEN transaction_type = 'purchase' ...)`**: Evaluates integer flags per row matches inside the grouped tracking context.
* **`AND (MAX(transaction_date) - MIN(transaction_date)) >= 29`**: Leverages Postgres' built-in native date arithmetic. Subtracting two explicit `DATE` fields natively returns an integer corresponding directly to elapsed calendar days, bypassing standard function wrappers entirely.
* **`AND (SUM(CASE WHEN transaction_type = 'refund' THEN 1.0 ELSE 0.0 END) / COUNT(*)) < 0.20`**: Like T-SQL, Postgres uses truncation mechanics on strict integer divisions. Injecting `1.0` yields a numeric float value, protecting the mathematical operation against unintended zeroing out.
* **`ORDER BY customer_id ASC;`**: Sets up index ordering compliance.

## 4. Oracle SQL 11.2

### Optimized Solution

```sql
SELECT 
    customer_id
FROM 
    customer_transactions
GROUP BY 
    customer_id
HAVING 
    SUM(CASE WHEN transaction_type = 'purchase' THEN 1 ELSE 0 END) >= 3
    AND (MAX(transaction_date) - MIN(transaction_date)) >= 29
    AND (SUM(CASE WHEN transaction_type = 'refund' THEN 1 ELSE 0 END) / COUNT(*)) < 0.20
ORDER BY 
    customer_id ASC;

```

### Line-by-Line Explanation

* **`SUM(CASE WHEN transaction_type = 'purchase' THEN 1 ELSE 0 END) >= 3`**: Standard Oracle PL/SQL conditional aggregator verification.
* **`AND (MAX(transaction_date) - MIN(transaction_date)) >= 29`**: Oracle natively converts direct calendar date modifications (`DATE - DATE`) into numeric fractional or absolute values denoting whole calendar days.
* **`AND (SUM(CASE WHEN transaction_type = 'refund' THEN 1 ELSE 0 END) / COUNT(*)) < 0.20`**: Unlike SQL Server or Postgres, Oracle's division operator `/` automatically casts values into precision floating numbers during division operations. Hence, standard whole numbers (`1` and `0`) function perfectly without manual fractional casting.
* **`ORDER BY customer_id ASC;`**: Finalizes output layout structure.

## 5. Python 3.10 with Pandas 2.2.2 & NumPy 1.26.4

### Optimized Vectorized Solution

```python
import pandas as pd


def find_loyal_customers(customer_transactions: pd.DataFrame) -> pd.DataFrame:
    # 1. Group and run aggregations in a single pass
    summary = customer_transactions.groupby("customer_id").agg(
        total_transactions=("transaction_type", "count"),
        purchases=(
            "transaction_type",
            lambda x: (x == "purchase").sum(),
        ),
        refunds=("transaction_type", lambda x: (x == "refund").sum()),
        min_date=("transaction_date", "min"),
        max_date=("transaction_date", "max"),
    )

    # 2. Calculate runtime properties via vector operations
    summary["active_days"] = (
        pd.to_datetime(summary["max_date"])
        - pd.to_datetime(summary["min_date"])
    ).dt.days
    summary["refund_rate"] = (
        summary["refunds"] / summary["total_transactions"]
    )

    # 3. Form boolean lookup evaluation masks
    loyal_mask = (
        (summary["purchases"] >= 3)
        & (summary["active_days"] >= 29)
        & (summary["refund_rate"] < 0.20)
    )

    # 4. Construct final structured table slice
    result = (
        summary[loyal_mask]
        .reset_index()[["customer_id"]]
        .sort_values(by="customer_id", ascending=True)
    )

    return result

```

### Line-by-Line Explanation

* **`customer_transactions.groupby("customer_id").agg(...)`**: Avoids slow iterative row loops by partitioning the working memory space by the index target key in a single execution step.
* **`total_transactions=('transaction_type', 'count')`**: Tallies absolute row metrics assigned to that specific entity.
* **`purchases=('transaction_type', lambda x: (x == 'purchase').sum())`**: Executes highly optimized element-wise comparisons over vectorized NumPy sub-arrays to filter and extract subset match counts.
* **`pd.to_datetime(...) - pd.to_datetime(...)`**: Explicitly casts string data entries into high-precision `datetime64` representations. Subtracting these outputs a Pandas `Timedelta` structure.
* **`.dt.days`**: Extracts raw integer components out of time delta structures, mirroring database-level date math functionality.
* **`summary['refunds'] / summary['total_transactions']`**: Performs an element-wise series division to determine refund rates.
* **`loyal_mask = (...) & (...) & (...)`**: Combines multiple boolean conditions using the bitwise AND (`&`) operator. This generates a fast truth-value matrix filter.
* **`summary[loyal_mask].reset_index()[['customer_id']]`**: Applies the filtration mask, elevates the target column back into an operational DataFrame property from the index layout, and slices out irrelevant metadata.
* **`.sort_values(by='customer_id', ascending=True)`**: Re-orders index rows to fulfill systemic constraints before returning dataframes.
