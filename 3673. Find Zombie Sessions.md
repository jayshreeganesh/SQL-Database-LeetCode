
# Problem Analysis: Find Zombie Sessions

The goal is to identify "Zombie Sessions" from user interaction logs. A session is flagged if it meets four specific criteria:
1. **Duration:** The total session duration is strictly greater than 30 minutes.
2. **Engagement:** The session contains at least 5 `scroll` events.
3. **Activity Ratio:** The ratio of `click` events to `scroll` events is strictly less than 0.20.
4. **Conversion:** No `purchase` events occurred during the session (`count = 0`).

---

## 1. MySQL 8.0 Solution

MySQL 8.0 allows clean filtering using aggregate functions inside the `HAVING` clause. Time differences are handled cleanly using `TIMESTAMPDIFF`.

### Code
```sql
SELECT 
    session_id,
    user_id,
    TIMESTAMPDIFF(MINUTE, MIN(event_timestamp), MAX(event_timestamp)) AS session_duration_minutes,
    COUNT(CASE WHEN event_type = 'scroll' THEN 1 END) AS scroll_count
FROM 
    app_events
GROUP BY 
    session_id, 
    user_id
HAVING 
    TIMESTAMPDIFF(MINUTE, MIN(event_timestamp), MAX(event_timestamp)) > 30
    AND COUNT(CASE WHEN event_type = 'scroll' THEN 1 END) >= 5
    AND (COUNT(CASE WHEN event_type = 'click' THEN 1 END) / COUNT(CASE WHEN event_type = 'scroll' THEN 1 END)) < 0.20
    AND COUNT(CASE WHEN event_type = 'purchase' THEN 1 END) = 0
ORDER BY 
    scroll_count DESC, 
    session_id ASC;

```

### Line-by-Line Explanation

* **`SELECT session_id, user_id, ...`**: Extracts the identifying attributes for each unique session.
* **`TIMESTAMPDIFF(MINUTE, MIN(event_timestamp), MAX(event_timestamp))`**: Calculates the difference in minutes between the first (`MIN`) and last (`MAX`) recorded event within that session block.
* **`COUNT(CASE WHEN event_type = 'scroll' THEN 1 END)`**: Uses conditional aggregation to count rows where the event is exactly a scroll. Non-matching rows result in `NULL`, which `COUNT()` safely ignores.
* **`FROM app_events GROUP BY session_id, user_id`**: Groups the raw event stream into distinct sessions per user.
* **`HAVING ... > 30`**: Enforces Condition 1 (Session duration must be longer than 30 minutes).
* **`AND COUNT(...) >= 5`**: Enforces Condition 2 (Ensures at least 5 scroll actions).
* **`AND (COUNT(click) / COUNT(scroll)) < 0.20`**: Enforces Condition 3. Since the previous line guarantees scrolls $\ge 5$, division by zero is impossible.
* **`AND COUNT(purchase) = 0`**: Enforces Condition 4 (Filters out any session where a purchase took place).
* **`ORDER BY scroll_count DESC, session_id ASC`**: Sorts results as requested.

## 2. MS SQL Server 2019 Solution

MS SQL Server uses `DATEDIFF` for time intervals and defaults to integer division. We must convert integers to floats to prevent decimal truncation.

### Code

```sql
SELECT 
    session_id,
    user_id,
    DATEDIFF(MINUTE, MIN(event_timestamp), MAX(event_timestamp)) AS session_duration_minutes,
    COUNT(CASE WHEN event_type = 'scroll' THEN 1 END) AS scroll_count
FROM 
    app_events
GROUP BY 
    session_id, 
    user_id
HAVING 
    DATEDIFF(MINUTE, MIN(event_timestamp), MAX(event_timestamp)) > 30
    AND COUNT(CASE WHEN event_type = 'scroll' THEN 1 END) >= 5
    AND (COUNT(CASE WHEN event_type = 'click' THEN 1 END) * 1.0 / COUNT(CASE WHEN event_type = 'scroll' THEN 1 END)) < 0.20
    AND COUNT(CASE WHEN event_type = 'purchase' THEN 1 END) = 0
ORDER BY 
    scroll_count DESC, 
    session_id ASC;

```

### Line-by-Line Explanation

* **`DATEDIFF(MINUTE, MIN(...), MAX(...))`**: Returns the count of minute boundaries crossed between the start and end of the session.
* **`COUNT(CASE WHEN event_type = 'scroll' THEN 1 END)`**: Tracks aggregate scroll counts per group.
* **`GROUP BY session_id, user_id`**: Consolidates the granular events into unique session blocks.
* **`HAVING DATEDIFF(...) > 30`**: Removes short/inactive sessions under 30 minutes.
* **`AND (COUNT(...) * 1.0 / COUNT(...)) < 0.20`**: **Crucial T-SQL Step.** Multiplying by `1.0` implicitly casts the numerator from an `INT` to a `DECIMAL`. Without this, `1 / 6` evaluates to `0` instead of `0.1666`.

## 3. PostgreSQL 16 Solution

PostgreSQL tracks intervals closely. Subtracting timestamps yields an `INTERVAL` type, which must be converted to seconds (`EPOCH`) to compute absolute float minutes.

### Code

```sql
SELECT 
    session_id,
    user_id,
    (EXTRACT(EPOCH FROM MAX(event_timestamp)) - EXTRACT(EPOCH FROM MIN(event_timestamp))) / 60 AS session_duration_minutes,
    COUNT(CASE WHEN event_type = 'scroll' THEN 1 END) AS scroll_count
FROM 
    app_events
GROUP BY 
    session_id, 
    user_id
HAVING 
    ((EXTRACT(EPOCH FROM MAX(event_timestamp)) - EXTRACT(EPOCH FROM MIN(event_timestamp))) / 60) > 30
    AND COUNT(CASE WHEN event_type = 'scroll' THEN 1 END) >= 5
    AND (COUNT(CASE WHEN event_type = 'click' THEN 1 END)::NUMERIC / COUNT(CASE WHEN event_type = 'scroll' THEN 1 END)) < 0.20
    AND COUNT(CASE WHEN event_type = 'purchase' THEN 1 END) = 0
ORDER BY 
    scroll_count DESC, 
    session_id ASC;

```

### Line-by-Line Explanation

* **`EXTRACT(EPOCH FROM MAX(dt)) - EXTRACT(EPOCH FROM MIN(dt))`**: Converts timestamps to Unix epoch timestamps (total seconds) and calculates the exact delta.
* **`/ 60`**: Converts the raw seconds difference into fractional minutes.
* **`COUNT(CASE WHEN event_type = 'scroll' THEN 1 END)`**: Captures the scroll counts per session.
* **`COUNT(...)::NUMERIC`**: Uses the PostgreSQL explicit cast operator (`::`) to turn the integer click count into a numeric value, avoiding integer truncation during division.
* **`HAVING ...`**: Evaluates aggregate conditions across duration, minimum scroll thresholds, low engagement click-ratios, and absence of conversion behaviors.

## 4. Oracle SQL 11.2 Solution

Oracle treats timestamp subtraction tightly, yielding an `INTERVAL DAY TO SECOND` type that can cause runtime extraction errors if handled improperly within aggregate groupings. Casting to a traditional `DATE` allows day-fraction arithmetic.

### Code

```sql
SELECT 
    session_id,
    user_id,
    (CAST(MAX(event_timestamp) AS DATE) - CAST(MIN(event_timestamp) AS DATE)) * 1440 AS session_duration_minutes,
    COUNT(CASE WHEN event_type = 'scroll' THEN 1 END) AS scroll_count
FROM 
    app_events
GROUP BY 
    session_id, 
    user_id
HAVING 
    ((CAST(MAX(event_timestamp) AS DATE) - CAST(MIN(event_timestamp) AS DATE)) * 1440) > 30
    AND COUNT(CASE WHEN event_type = 'scroll' THEN 1 END) >= 5
    AND (COUNT(CASE WHEN event_type = 'click' THEN 1 END) * 1.0 / COUNT(CASE WHEN event_type = 'scroll' THEN 1 END)) < 0.20
    AND COUNT(CASE WHEN event_type = 'purchase' THEN 1 END) = 0
ORDER BY 
    scroll_count DESC, 
    session_id ASC;

```

### Line-by-Line Explanation

* **`CAST(... AS DATE)`**: Converts high-precision timestamps down to Oracle `DATE` structures (which still preserve hours, minutes, and seconds safely).
* **`MAX(DATE) - MIN(DATE)`**: Subtracting Oracle dates yields a numeric value representing the delta in **days** (e.g., `0.5` = 12 hours).
* **`* 1440`**: Multiplies the day delta by 1440 (24 hours $\times$ 60 minutes) to convert days directly into total runtime minutes, bypassing complex interval extract constraints.
* **`COUNT(CASE WHEN ... END) * 1.0`**: Converts standard count numbers into decimal formats to fulfill precision division operations safely.

## 5. Python 3.10 / Pandas 2.2.2 Solution

Pandas reads text payloads as raw strings. The data series must be explicitly parsed to datetime formats before execution.

### Code

```python
import pandas as pd
import numpy as np

def find_zombie_sessions(app_events: pd.DataFrame) -> pd.DataFrame:
    # 1. Parse dates safely from object string formats
    app_events['event_timestamp'] = pd.to_datetime(app_events['event_timestamp'])
    
    # 2. Vectorized Grouping & Aggregation
    grouped = app_events.groupby(['session_id', 'user_id']).agg(
        min_time=('event_timestamp', 'min'),
        max_time=('event_timestamp', 'max'),
        scroll_count=('event_type', lambda x: (x == 'scroll').sum()),
        click_count=('event_type', lambda x: (x == 'click').sum()),
        purchase_count=('event_type', lambda x: (x == 'purchase').sum())
    ).reset_index()
    
    # 3. Compute session minutes via continuous float transformation
    grouped['session_duration_minutes'] = (grouped['max_time'] - grouped['min_time']).dt.total_seconds() / 60.0
    
    # 4. Generate Boolean Masks matching criteria
    c1 = grouped['session_duration_minutes'] > 30
    c2 = grouped['scroll_count'] >= 5
    c3 = (grouped['click_count'] / grouped['scroll_count']) < 0.20
    c4 = grouped['purchase_count'] == 0
    
    # 5. Apply Boolean Filter Matrices
    zombie_sessions = grouped[c1 & c2 & c3 & c4].copy()
    
    # 6. Format Output Shape and Ordering
    result = zombie_sessions[[
        'session_id', 
        'user_id', 
        'session_duration_minutes', 
        'scroll_count'
    ]]
    
    result = result.sort_values(
        by=['scroll_count', 'session_id'], 
        ascending=[False, True]
    )
    
    return result

```

### Line-by-Line Explanation

* **`pd.to_datetime(...)`**: Converts string date objects into true `datetime64[ns]` formats to enable mathematical date properties.
* **`.groupby(['session_id', 'user_id']).agg(...)`**: Builds session buckets and applies optimization rules simultaneously.
* **`lambda x: (x == 'scroll').sum()`**: Evaluates individual true values within arrays to count events efficiently.
* **`.dt.total_seconds() / 60.0`**: Subtracting datetimes creates a `timedelta` column. We call `.total_seconds()` to get a numeric float series, then scale it to minutes.
* **`c1 & c2 & c3 & c4`**: Executes a fast, bitwise element-by-element intersection mask across all conditions.
* **`sort_values(by=[...], ascending=[False, True])`**: Sorts the resulting sessions by scroll velocity descending, breaking ties with structural session indexes ascending.
