# Complete Solution Guide: LeetCode 3580 - Find Consistently Improving Employees

This document provides optimized, clean implementations across five languages/frameworks: **MySQL 8.0**, **MS SQL Server 2019**, **PostgreSQL 16**, **Oracle SQL 11.2**, and **Python 3.10 (Pandas/NumPy)**.

Two distinct approaches are detailed below: the **Window + Pivot Approach** and the **Window + Lead/Lag Approach**.

## 1. MySQL 8.0

### Approach 1: Window Functions with Conditional Aggregation (Pivot)

This approach ranks the reviews sequentially per employee and uses `MAX(CASE WHEN...)` to pivot the rows into side-by-side comparative columns.

```sql
WITH RankedReviews AS (
    SELECT 
        employee_id,
        rating,
        ROW_NUMBER() OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS rn
    FROM performance_reviews
),
LastThreeReviews AS (
    SELECT 
        employee_id,
        MAX(CASE WHEN rn = 1 THEN rating END) AS latest_rating,
        MAX(CASE WHEN rn = 2 THEN rating END) AS second_latest_rating,
        MAX(CASE WHEN rn = 3 THEN rating END) AS third_latest_rating,
        COUNT(*) AS review_count
    FROM RankedReviews
    WHERE rn <= 3
    GROUP BY employee_id
)
SELECT 
    r.employee_id,
    e.name,
    (r.latest_rating - r.third_latest_rating) AS improvement_score
FROM LastThreeReviews r
JOIN employees e ON r.employee_id = e.employee_id
WHERE r.review_count = 3 
  AND r.latest_rating > r.second_latest_rating 
  AND r.second_latest_rating > r.third_latest_rating
ORDER BY improvement_score DESC, e.name ASC;

```

#### Line-by-Line Explanation

* `WITH RankedReviews AS (...)`: Declares the first Common Table Expression (CTE) to order reviews chronologically per employee.
* `ROW_NUMBER() OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS rn`: Evaluates rows per `employee_id`. The most recent review gets `rn = 1`, the previous gets `rn = 2`, and so on.
* `LastThreeReviews AS (...)`: Filters down to only the relevant review pool (`WHERE rn <= 3`) and groups by `employee_id`.
* `MAX(CASE WHEN rn = 1 THEN rating END) AS latest_rating`: Conditional aggregation pattern that extracts the rating associated with `rn = 1` into its own scalar column.
* `COUNT(*) AS review_count`: Tracks the size of the grouped block per employee to validate the constraint rule.
* `WHERE r.review_count = 3`: Ensures that employees with fewer than 3 reviews are completely removed from evaluation.
* `AND r.latest_rating > r.second_latest_rating AND ...`: Evaluates strict inequality conditions ensuring monotonic performance improvement over time.
* `ORDER BY improvement_score DESC, e.name ASC`: Formats the presentation array output sequence exactly as specified.

### Approach 2: Inline Window Interrogation (`LEAD`)

This variation evaluates previous historical review dates relative to a base cursor position without grouping records beforehand.

```sql
WITH SequentialHistory AS (
    SELECT 
        employee_id,
        rating AS latest_rating,
        LEAD(rating, 1) OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS second_latest_rating,
        LEAD(rating, 2) OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS third_latest_rating,
        ROW_NUMBER() OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS rn
    FROM performance_reviews
)
SELECT 
    h.employee_id,
    e.name,
    (h.latest_rating - h.third_latest_rating) AS improvement_score
FROM SequentialHistory h
JOIN employees e ON h.employee_id = e.employee_id
WHERE h.rn = 1
  AND h.second_latest_rating IS NOT NULL
  AND h.third_latest_rating IS NOT NULL
  AND h.latest_rating > h.second_latest_rating
  AND h.second_latest_rating > h.third_latest_rating
ORDER BY improvement_score DESC, e.name ASC;

```

#### Line-by-Line Explanation

* `LEAD(rating, 1) OVER (...)`: Looks forward into the descending ordered pipeline sequence to pull the 2nd most recent record value into the cursor context row of the 1st record.
* `LEAD(rating, 2) OVER (...)`: Looks forward two steps into the sequence window to capture the 3rd most recent review value.
* `WHERE h.rn = 1`: Pins evaluation explicitly to the newest timeline review row context per individual employee.
* `AND h.third_latest_rating IS NOT NULL`: Enforces that at least 3 reviews exist for that employee, as a 3rd review absence would cause `LEAD(rating, 2)` to return `NULL`.

### Approach 2: T-SQL Native `FIRST_VALUE` and Windowing Offset

```sql
WITH HistoricalSequences AS (
    SELECT 
        employee_id,
        rating,
        LEAD(rating, 1) OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS prev1,
        LEAD(rating, 2) OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS prev2,
        ROW_NUMBER() OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS seq_id
    FROM performance_reviews
)
SELECT 
    s.employee_id,
    e.name,
    (s.rating - s.prev2) AS improvement_score
FROM HistoricalSequences s
INNER JOIN employees e ON s.employee_id = e.employee_id
WHERE s.seq_id = 1
  AND s.prev1 IS NOT NULL
  AND s.prev2 IS NOT NULL
  AND s.rating > s.prev1
  AND s.prev1 > s.prev2
ORDER BY improvement_score DESC, e.name ASC;

```

#### Line-by-Line Explanation

* `LEAD(rating, 1)` / `LEAD(rating, 2)`: Pulls data points forward from chronologically older tracking points relative to the current evaluation point.
* `WHERE s.seq_id = 1`: Restricts the final filtering stage exclusively to the actual newest performance evaluation record row.
* `AND s.rating > s.prev1 AND s.prev1 > s.prev2`: Validates that the scores are strictly increasing across all three timeframes.

### Approach 2: Postgres Filtered Window Functions

```sql
WITH WindowAnalyses AS (
    SELECT 
        employee_id,
        rating,
        ROW_NUMBER() OVER (PARTITION BY employee_id ORDER BY review_date DESC) as row_seq,
        LEAD(rating, 1) OVER (PARTITION BY employee_id ORDER BY review_date DESC) as next_rating,
        LEAD(rating, 2) OVER (PARTITION BY employee_id ORDER BY review_date DESC) as following_rating
    FROM performance_reviews
)
SELECT 
    w.employee_id,
    e.name,
    (w.rating - w.following_rating) AS improvement_score
FROM WindowAnalyses w
JOIN employees e ON w.employee_id = e.employee_id
WHERE w.row_seq = 1
  AND w.following_rating IS NOT NULL
  AND w.rating > w.next_rating
  AND w.next_rating > w.following_rating
ORDER BY improvement_score DESC, e.name ASC;

```

#### Line-by-Line Explanation

* `LEAD(rating, 1)`: Accesses data from subsequent rows within the partition without needing a self-join.
* `WHERE w.row_seq = 1`: Filters the result set to evaluate only the most recent review for each employee.
* `AND w.rating > w.next_rating`: Verifies that the current rating is higher than the previous one, confirming steady improvement.

### Approach 2: Positional Windowing Lookahead

```sql
WITH ChronoTrack AS (
    SELECT 
        employee_id,
        rating AS cur_r,
        LEAD(rating, 1) OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS prev_r1,
        LEAD(rating, 2) OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS prev_r2,
        ROW_NUMBER() OVER (PARTITION BY employee_id ORDER BY review_date DESC) AS rnum
    FROM performance_reviews
)
SELECT 
    c.employee_id,
    e.name,
    (c.cur_r - c.prev_r2) AS improvement_score
FROM ChronoTrack c
INNER JOIN employees e ON c.employee_id = e.employee_id
WHERE c.rnum = 1
  AND c.prev_r1 IS NOT NULL
  AND c.prev_r2 IS NOT NULL
  AND c.cur_r > c.prev_r1
  AND c.prev_r1 > c.prev_r2
ORDER BY improvement_score DESC, e.name ASC;

```

#### Line-by-Line Explanation

* `LEAD(rating, 1)`: Navigates the partition backwards in time (due to `ORDER BY review_date DESC`) to fetch the preceding review rating.
* `WHERE c.rnum = 1`: Targets the absolute latest chronological row step record per employee group.
* `AND c.prev_r1 IS NOT NULL`: Filters out entries that do not have the required historical review depth.

## 5. Python 3.10 with Pandas 2.2.2 and NumPy 1.26.4

### Approach 1: Vectorized Sorting, Cumulative Counting, and Pivoting

```python
import pandas as pd
import numpy as np

def find_consistently_improving_employees_pivot(employees: pd.DataFrame, performance_reviews: pd.DataFrame) -> pd.DataFrame:
    # 1. Sort reviews by employee and date descending
    df = performance_reviews.sort_values(by=['employee_id', 'review_date'], ascending=[True, False]).copy()
    
    # 2. Assign dynamic row numbers per employee group
    df['rn'] = df.groupby('employee_id').cumcount() + 1
    
    # 3. Restrict processing window to the last 3 reviews
    top3 = df[df['rn'] <= 3]
    
    # 4. Pivot row values into explicit tracking data columns
    pivoted = top3.pivot(index='employee_id', columns='rn', values='rating')
    pivoted.columns = ['latest_rating', 'second_latest_rating', 'third_latest_rating']
    
    # 5. Build vectorized evaluations to filter records safely
    valid_mask = (
        pivoted.notna().all(axis=1) & 
        (pivoted['latest_rating'] > pivoted['second_latest_rating']) & 
        (pivoted['second_latest_rating'] > pivoted['third_latest_rating'])
    )
    
    filtered_pivoted = pivoted[valid_mask].reset_index()
    
    # 6. Merge with employee details and calculate the improvement score
    result = filtered_pivoted.merge(employees, on='employee_id', how='inner')
    result['improvement_score'] = result['latest_rating'] - result['third_latest_rating']
    
    # 7. Format and sort the final DataFrame
    final_df = result[['employee_id', 'name', 'improvement_score']]
    return final_df.sort_values(by=['improvement_score', 'name'], ascending=[False, True])

```

#### Line-by-Line Explanation

* `sort_values(by=['employee_id', 'review_date'], ascending=[True, False])`: Orders the underlying array block cleanly by date in descending order.
* `.groupby('employee_id').cumcount() + 1`: Computes a fast sequence count array using optimized C-extensions under the hood.
* `top3.pivot(...)`: Reshapes the DataFrame, converting row values into structured comparative features.
* `pivoted.notna().all(axis=1)`: Creates a boolean mask to ensure all three review columns contain valid numerical values.
* `filtered_pivoted.merge(...)`: Performs a vectorized database-style inner join operation.

### Approach 2: Vectorized Vector Offsets (`shift`)

```python
import pandas as pd
import numpy as np

def find_consistently_improving_employees_shift(employees: pd.DataFrame, performance_reviews: pd.DataFrame) -> pd.DataFrame:
    # 1. Order historical review records chronologically
    df = performance_reviews.sort_values(by=['employee_id', 'review_date'], ascending=True).copy()
    
    # 2. Compute shifted values within each employee group
    df['prev_rating_1'] = df.groupby('employee_id')['rating'].shift(1)
    df['prev_rating_2'] = df.groupby('employee_id')['rating'].shift(2)
    
    # 3. Identify the most recent review for each employee
    df['is_latest'] = df.groupby('employee_id')['review_date'].rank(method='max', ascending=False) == 1
    
    # 4. Filter for records that meet the continuous improvement criteria
    mask = (
        df['is_latest'] &
        df['prev_rating_1'].notna() &
        df['prev_rating_2'].notna() &
        (df['rating'] > df['prev_rating_1']) &
        (df['prev_rating_1'] > df['prev_rating_2'])
    )
    
    improving_df = df[mask].copy()
    
    # 5. Compute the improvement score
    improving_df['improvement_score'] = improving_df['rating'] - improving_df['prev_rating_2']
    
    # 6. Combine with employee info and sort the results
    result = improving_df.merge(employees, on='employee_id', how='inner')
    return result[['employee_id', 'name', 'improvement_score']].sort_values(
        by=['improvement_score', 'name'], ascending=[False, True]
    )

```

#### Line-by-Line Explanation

* `df.groupby('employee_id')['rating'].shift(1)`: Shifts column values down by 1 row within each group, pulling the previous chronological rating into the current row context.
* `rank(method='max', ascending=False) == 1`: Creates a boolean indicator that marks the newest available record row for each employee.
* `mask = (...)`: Combines the individual logical tracking criteria into a single evaluation operation.
* `improving_df['rating'] - improving_df['prev_rating_2']`: Vectorized subtraction that calculates the total rating improvement.
