# LeetCode: Analyze Subscription Conversion

## Problem Description
Calculate the average activity duration for users who converted from a free trial to a paid subscription, rounded to two decimal places. The final output must only include users who have records for both `'free_trial'` and `'paid'` activity types, sorted by `user_id` in ascending order.

---

## 1. MySQL
MySQL allows straightforward conditional aggregation. `AVG()` automatically ignores `NULL` values, preventing non-matching rows from skewing the averages.

```sql
SELECT 
    user_id,
    ROUND(AVG(CASE WHEN activity_type = 'free_trial' THEN activity_duration END), 2) AS trial_avg_duration,
    ROUND(AVG(CASE WHEN activity_type = 'paid' THEN activity_duration END), 2) AS paid_avg_duration
FROM 
    UserActivity
GROUP BY 
    user_id
HAVING 
    COUNT(CASE WHEN activity_type = 'free_trial' THEN 1 END) > 0
    AND COUNT(CASE WHEN activity_type = 'paid' THEN 1 END) > 0
ORDER BY 
    user_id ASC;

```

---

## 2. MS SQL Server (T-SQL)

In SQL Server, running `AVG()` on an integer column results in integer division (truncation). To preserve precision before rounding, the column must be explicitly cast to a `FLOAT`.

```sql
SELECT 
    user_id,
    ROUND(AVG(CASE WHEN activity_type = 'free_trial' THEN CAST(activity_duration AS FLOAT) END), 2) AS trial_avg_duration,
    ROUND(AVG(CASE WHEN activity_type = 'paid' THEN CAST(activity_duration AS FLOAT) END), 2) AS paid_avg_duration
FROM 
    UserActivity
GROUP BY 
    user_id
HAVING 
    COUNT(CASE WHEN activity_type = 'free_trial' THEN 1 END) > 0
    AND COUNT(CASE WHEN activity_type = 'paid' THEN 1 END) > 0
ORDER BY 
    user_id ASC;

```

## 3. PostgreSQL

Similar to SQL Server, PostgreSQL truncates integer division. Using the type-cast shorthand `::NUMERIC` ensures high-precision calculations before passing the value to `ROUND()`.

```sql
SELECT 
    user_id,
    ROUND(AVG(CASE WHEN activity_type = 'free_trial' THEN activity_duration::NUMERIC END), 2) AS trial_avg_duration,
    ROUND(AVG(CASE WHEN activity_type = 'paid' THEN activity_duration::NUMERIC END), 2) AS paid_avg_duration

HAVING

    user_id ASC;

```

## 5. Python (Pandas)

Using `pivot_table` acts as an elegant aggregation function. A tiny epsilon (`1e-9`) is added right before rounding to prevent Python's default **banker's rounding** (round-to-even) from causing arithmetic mismatches against the judge.

```python
import pandas as pd

def analyze_subscription_conversion(user_activity: pd.DataFrame) -> pd.DataFrame:
    # Pivot DataFrame to find the mean activity_duration per user/activity type
    pivot_df = user_activity.pivot_table(
        index='user_id',
        columns='activity_type',
        values='activity_duration',
        aggfunc='mean'
    )
    
    # Handle missing column structural edge cases
    for col in ['free_trial', 'paid']:
        if col not in pivot_df.columns:
            pivot_df[col] = None
            
    # Filter out users who haven't undergone a complete conversion 
    filtered_df = pivot_df[pivot_df['free_trial'].notna() & pivot_df['paid'].notna()].reset_index()
    
    # Select and rename output metrics
    result = filtered_df[['user_id', 'free_trial', 'paid']].rename(columns={
        'free_trial': 'trial_avg_duration',
        'paid': 'paid_avg_duration'
    })
    result.columns.name = None 
    
    # Bypass banker's rounding quirk with an epsilon offset
    result['trial_avg_duration'] = (result['trial_avg_duration'] + 1e-9).round(2)
    result['paid_avg_duration'] = (result['paid_avg_duration'] + 1e-9).round(2)
    
    # Sort and return index-aligned data
    return result.sort_values(by='user_id').reset_index(drop=True)

```
