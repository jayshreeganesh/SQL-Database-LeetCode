## 1. MySQL 8.0 Solution

### Code
```sql
WITH UserSummary AS (
    SELECT 
        user_id,
        plan_name,
        monthly_amount,
        event_type,
        ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY event_date DESC, event_id DESC) as rn,
        MAX(monthly_amount) OVER(PARTITION BY user_id) as max_historical_amount,
        DATEDIFF(MAX(event_date) OVER(PARTITION BY user_id), MIN(event_date) OVER(PARTITION BY user_id)) as days_as_subscriber,
        SUM(CASE WHEN event_type = 'downgrade' THEN 1 ELSE 0 END) OVER(PARTITION BY user_id) as downgrade_count
    FROM subscription_events
)
SELECT 
    user_id,
    plan_name AS current_plan,
    monthly_amount AS current_monthly_amount,
    max_historical_amount,
    days_as_subscriber
FROM UserSummary
WHERE rn = 1  
  AND event_type <> 'cancel' 
  AND downgrade_count > 0 
  AND monthly_amount < 0.5 * max_historical_amount 
  AND days_as_subscriber >= 60 
ORDER BY 
    days_as_subscriber DESC, 
    user_id ASC;

```

### Line-by-Line Explanation

* **`WITH UserSummary AS (`**: Declares a Common Table Expression (CTE) named `UserSummary` to calculate windowed statistics before final filtering.
* **`ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY event_date DESC, event_id DESC) as rn`**: Computes a sequential integer ranking for each user's timeline. Ordering by `event_date DESC` and breaking ties with `event_id DESC` guarantees that `rn = 1` evaluates to the absolute latest record (current state).
* **`MAX(monthly_amount) OVER(PARTITION BY user_id) as max_historical_amount`**: Computes the highest subscription cost the user ever paid across their entire history.
* **`DATEDIFF(...) as days_as_subscriber`**: Computes total tenure duration. MySQL's `DATEDIFF(expr1, expr2)` calculates `expr1 - expr2` in days. Here, it subtracts the earliest tracking record (`MIN(event_date)`) from the final milestone timeline entry (`MAX(event_date)`).
* **`SUM(CASE WHEN event_type = 'downgrade' THEN 1 ELSE 0 END) OVER(...) as downgrade_count`**: Scans the user partition profile history to count occurrences of a `'downgrade'`.
* **`WHERE rn = 1`**: Isolates only rows describing the user's latest active or inactive state.
* **`AND event_type <> 'cancel'`**: Rule 1 compliance: drops users whose current state is terminated.
* **`AND downgrade_count > 0`**: Rule 2 compliance: requires at least one downgrade flag in their historical logs.
* **`AND monthly_amount < 0.5 * max_historical_amount`**: Rule 3 compliance: filters for users whose current pricing Tier revenue dropped below 50% of their historical max peak.
* **`AND days_as_subscriber >= 60`**: Rule 4 compliance: limits analysis to customers retained for 60 days or longer.
* **`ORDER BY days_as_subscriber DESC, user_id ASC`**: Sorts the output descending by tenure, breaking ties with ascending user identification IDs.

### Line-by-Line Explanation

* **`DATEDIFF(day, MIN(...), MAX(...))`**: T-SQL (MS SQL Server) syntax requires defining the datepart interval type (`day`) as the first argument, followed by the explicit `start_date` and `end_date` parameters. This replaces the two-argument syntax used in MySQL.
* **`ROW_NUMBER() / MAX() / SUM() OVER(...)`**: T-SQL executes window frame distributions identically across partitioned indexes.
* **`event_type <> 'cancel'`**: Uses standard ANSI standard inequality operators to isolate active clients in the terminal projection layer.

## 3. PostgreSQL 16 Solution


### Line-by-Line Explanation

* **`(MAX(event_date) OVER(...) - MIN(event_date) OVER(...))`**: PostgreSQL does not require an explicit function call like `DATEDIFF`. Subtracting two `DATE` types natively yields an integer representing the exact count difference in days.
* **Numeric Multipliers (`0.5 * max_historical_amount`)**: PostgreSQL 16 handles internal runtime decimal conversions automatically without throwing explicit type casting errors during condition verification.

## 5. Python 3.10 with Pandas 2.2.2 & NumPy 1.26.4 Solution

### Code

```python
import pandas as pd
import numpy as np

def find_churn_risk_customers(subscription_events: pd.DataFrame) -> pd.DataFrame:
    # 1. Standardize timestamp formatting
    subscription_events['event_date'] = pd.to_datetime(subscription_events['event_date'])
    
    # 2. Sort values systematically to replicate row partitioning models
    df_sorted = subscription_events.sort_values(
        by=['user_id', 'event_date', 'event_id'], 
        ascending=[True, False, False]
    )
    
    # 3. Fetch the latest row element per distinct identifier block
    current_state = df_sorted.drop_duplicates(subset=['user_id'], keep='first')
    
    # 4. Extract metrics via grouped matrix aggregation
    user_metrics = subscription_events.groupby('user_id').agg(
        max_historical_amount=('monthly_amount', 'max'),
        min_date=('event_date', 'min'),
        max_date=('event_date', 'max'),
        downgrade_count=('event_type', lambda x: (x == 'downgrade').sum())
    ).reset_index()
    
    # 5. Extract integer delta days scalar conversions
    user_metrics['days_as_subscriber'] = (user_metrics['max_date'] - user_metrics['min_date']).dt.days
    
    # 6. Combine active slice states against cumulative aggregates
    merged = pd.merge(current_state, user_metrics, on='user_id')
    
    # 7. Apply vectorized filtering logical constraints
    churn_risks = merged[
        (merged['event_type'] != 'cancel') &
        (merged['downgrade_count'] > 0) &
        (merged['monthly_amount'] < 0.5 * merged['max_historical_amount']) &
        (merged['days_as_subscriber'] >= 60)
    ]
    
    # 8. Clean columns & rename target fields
    output = churn_risks[[
        'user_id', 
        'plan_name', 
        'monthly_amount', 
        'max_historical_amount', 
        'days_as_subscriber'
    ]].rename(columns={
        'plan_name': 'current_plan',
        'monthly_amount': 'current_monthly_amount'
    })
    
    # 9. Sort outputs matching terminal schema specification rules
    output = output.sort_values(by=['days_as_subscriber', 'user_id'], ascending=[False, True])
    
    return output

```

### Line-by-Line Explanation

* **`pd.to_datetime(...)`**: Converts input string/object dates into real `datetime64[ns]` formats to enable exact time delta operations.
* **`sort_values(by=[...], ascending=[True, False, False])`**: Organizes rows by user tracking numbers ascending, but pushes structural history changes down chronologically by setting date and record ID paths to `False` (descending order).
* **`drop_duplicates(subset=['user_id'], keep='first')`**: Replicates SQL's `ROW_NUMBER() = 1` logic by keeping only the top (most recent) record per user.
* **`groupby('user_id').agg(...)`**: Vectorizes mathematical computations across independent identifier buckets to calculate historical max amounts, minimum dates, maximum dates, and occurrences of downgrades.
* **`.dt.days`**: Translates internal Pandas `Timedelta` arrays down into plain integer numbers representing days for logical comparison filtering.
* **`pd.merge(current_state, user_metrics, on='user_id')`**: Connects current subscription states with historical metadata metrics across identical `user_id` joins.
* **`churn_risks = merged[...]`**: Applies array-level boolean logic gates to filter out cancelled users, ensure downgrade counts are above zero, ensure the current price is less than 50% of their peak, and check if tenure is 60+ days.
* **`rename(columns={...})`**: Maps structural staging data names back onto standard expected clean reporting labels (`current_plan` and `current_monthly_amount`).
* **`sort_values(..., ascending=[False, True])`**: Performs final tabular sorting based on the requested specification parameters.
