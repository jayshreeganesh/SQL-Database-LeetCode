
# 3611. Find Overbooked Employees — Complete Solution Guide

This guide provides robust, production-ready solutions across 5 major data environments to identify "meeting-heavy" employees (those exceeding 20 meeting hours in a single Monday-to-Sunday week for at least 2 distinct weeks).

---

## 1. MySQL 8.0 Solution

### Query
```sql
WITH HeavyWeeks AS (
    SELECT 
        employee_id,
        YEARWEEK(meeting_date, 3) AS week_id
    FROM meetings
    GROUP BY employee_id, YEARWEEK(meeting_date, 3)
    HAVING SUM(duration_hours) > 20
)
SELECT 
    e.employee_id,
    e.employee_name,
    e.department,
    COUNT(hw.week_id) AS meeting_heavy_weeks
FROM employees e
INNER JOIN HeavyWeeks hw ON e.employee_id = hw.employee_id
GROUP BY e.employee_id, e.employee_name, e.department
HAVING COUNT(hw.week_id) >= 2
ORDER BY meeting_heavy_weeks DESC, e.employee_name ASC;

```

### Line-by-Line Explanation

* **`WITH HeavyWeeks AS (`**: Defines a Common Table Expression (CTE) to temporarily isolate employees' individual overbooked weeks.
* **`SELECT employee_id, YEARWEEK(meeting_date, 3) AS week_id`**: Selects the employee and transforms the meeting date into a combined year-week numerical identifier. Mode `3` specifies that the week starts on a Monday and adheres to the ISO 8601 standard.
* **`FROM meetings`**: References the source table containing all log entries for meetings.
* **`GROUP BY employee_id, YEARWEEK(meeting_date, 3)`**: Aggregates the records so that meeting durations can be evaluated per employee per individual unique week.
* **`HAVING SUM(duration_hours) > 20`**: Evaluates the group sum; only groups where the total accumulated meeting time strictly surpasses 20 hours are kept.
* **`SELECT e.employee_id, e.employee_name, ... COUNT(hw.week_id)`**: References columns from the primary `employees` table and counts how many individual qualifying week keys exist for each employee.
* **`INNER JOIN HeavyWeeks hw ON e.employee_id = hw.employee_id`**: Performs an inner join to pair employee descriptive metadata with their respective heavy-meeting weeks.
* **`GROUP BY e.employee_id, e.employee_name, e.department`**: Regroups the combined dataset at the employee profile level to count their overall count of heavy weeks.
* **`HAVING COUNT(hw.week_id) >= 2`**: Suppresses any employees who did not experience at least 2 weeks of high meeting volumes.
* **`ORDER BY meeting_heavy_weeks DESC, e.employee_name ASC;`**: Orders the output exactly as requested—highest overbooked week frequency first, sorting alphabetically by name as a tie-breaker.

## 2. MS SQL Server 2019 Solution

### Query

```sql
WITH HeavyWeeks AS (
    SELECT 
        employee_id,
        YEAR(meeting_date) AS meeting_year,
        DATEPART(iso_week, meeting_date) AS week_id
    FROM meetings
    GROUP BY employee_id, YEAR(meeting_date), DATEPART(iso_week, meeting_date)
    HAVING SUM(duration_hours) > 20
)
SELECT 
    e.employee_id,
    e.employee_name,
    e.department,
    COUNT(*) AS meeting_heavy_weeks
FROM employees e
INNER JOIN HeavyWeeks hw ON e.employee_id = hw.employee_id
GROUP BY e.employee_id, e.employee_name, e.department
HAVING COUNT(*) >= 2
ORDER BY meeting_heavy_weeks DESC, e.employee_name ASC;

```

### Line-by-Line Explanation

* **`YEAR(meeting_date) AS meeting_year`**: Extracts the absolute calendar year to ensure week tracking does not conflict when evaluating multi-year transactional datasets.
* **`DATEPART(iso_week, meeting_date) AS week_id`**: Extracts the ISO 8601 week position index. The use of `iso_week` ensures T-SQL strictly sets Monday as day 1 of the week, independent of server-level configuration variables like `@@DATEFIRST`.
* **`GROUP BY employee_id, YEAR(meeting_date), DATEPART(iso_week, meeting_date)`**: Groups rows simultaneously by employee, year, and ISO week boundary to partition sums correctly.
* **`HAVING SUM(duration_hours) > 20`**: Imposes a filter evaluating the aggregate window to find periods surpassing 20 hours.
* **`COUNT(*) AS meeting_heavy_weeks`**: Evaluates the row frequency per employee within the inner-joined CTE dataset to quantify total overloaded periods.
* **`HAVING COUNT(*) >= 2`**: Re-filters the final structural summary to exclude anyone holding less than 2 high-workload periods.

## 3. PostgreSQL 16 Solution

### Query

```sql
WITH HeavyWeeks AS (
    SELECT 
        employee_id,
        DATE_TRUNC('week', meeting_date) AS week_start
    FROM meetings
    GROUP BY employee_id, DATE_TRUNC('week', meeting_date)
    HAVING SUM(duration_hours) > 20
)
SELECT 
    e.employee_id,
    e.employee_name,
    e.department,
    COUNT(hw.week_start) AS meeting_heavy_weeks
FROM employees e
INNER JOIN HeavyWeeks hw ON e.employee_id = hw.employee_id
GROUP BY e.employee_id, e.employee_name, e.department
HAVING COUNT(hw.week_start) >= 2
ORDER BY meeting_heavy_weeks DESC, e.employee_name ASC;

```

### Line-by-Line Explanation

* **`DATE_TRUNC('week', meeting_date) AS week_start`**: Truncates the exact raw timestamp/date down to the exact Monday starting that respective week. This serves as a unique calendar time value, natively solving both year transitions and Monday-start requirements.
* **`GROUP BY employee_id, DATE_TRUNC('week', meeting_date)`**: Groups the target record logs on both individual employee IDs and their normalized week-start date timestamps.
* **`HAVING SUM(duration_hours) > 20`**: Isolates and preserves only the specific Monday groups where accumulated hours exceed 20.
* **`COUNT(hw.week_start)`**: Tallies up the array of distinct truncated date keys assigned to the employee to obtain their meeting-heavy week tally.

## 4. Oracle SQL 11.2 Solution

### Query

```sql
WITH HeavyWeeks AS (
    SELECT 
        employee_id,
        TO_CHAR(meeting_date, 'IYYYIW') AS week_id
    FROM meetings
    GROUP BY employee_id, TO_CHAR(meeting_date, 'IYYYIW')
    HAVING SUM(duration_hours) > 20
)
SELECT 
    e.employee_id,
    e.employee_name,
    e.department,
    COUNT(hw.week_id) AS meeting_heavy_weeks
FROM employees e
INNER JOIN HeavyWeeks hw ON e.employee_id = hw.employee_id
GROUP BY e.employee_id, e.employee_name, e.department
HAVING COUNT(hw.week_id) >= 2
ORDER BY meeting_heavy_weeks DESC, e.employee_name ASC;

```

### Line-by-Line Explanation

* **`TO_CHAR(meeting_date, 'IYYYIW') AS week_id`**: Formats the date to a string combining the ISO year (`IYYY`) and ISO week (`IW`). In Oracle, `IW` enforces that a week starts on Monday, and `IYYY` prevents errors when the first or last week of a year overlaps across calendar boundaries.
* **`GROUP BY employee_id, TO_CHAR(meeting_date, 'IYYYIW')`**: Segregates raw records by employee id along with their respective calculated string time identifier.
* **`HAVING SUM(duration_hours) > 20`**: Drops any employee-week rows from the pipeline where meeting durations are equal to or less than 20 hours.

## 5. Python 3.10 with Pandas 2.2.2 Solution

### Code

```python
import pandas as pd
import numpy as np

def find_overbooked_employees(employees: pd.DataFrame, meetings: pd.DataFrame) -> pd.DataFrame:
    # Ensure date columns are explicitly treated as datetime objects
    meetings['meeting_date'] = pd.to_datetime(meetings['meeting_date'])
    
    # Step 1: Assign each meeting to a week ending on Sunday (starts on Monday)
    meetings['week_id'] = meetings['meeting_date'].dt.to_period('W-SUN')
    
    # Step 2: Group by employee and week to compute total duration hours
    weekly_hours = (
        meetings.groupby(['employee_id', 'week_id'])['duration_hours']
        .sum()
        .reset_index()
    )
    
    # Step 3: Filter for weeks exceeding 20 hours
    heavy_weeks = weekly_hours[weekly_hours['duration_hours'] > 20]
    
    # Step 4: Count how many heavy weeks each employee accumulated
    heavy_week_counts = (
        heavy_weeks.groupby('employee_id')
        .size()
        .reset_index(name='meeting_heavy_weeks')
    )
    
    # Step 5: Filter for employees with 2 or more heavy weeks
    overbooked_ids = heavy_week_counts[heavy_week_counts['meeting_heavy_weeks'] >= 2]
    
    # Step 6: Merge back with employees dataframe to retrieve descriptive metadata
    result = pd.merge(employees, overbooked_ids, on='employee_id', how='inner')
    
    # Step 7: Sort by meeting_heavy_weeks (descending) and employee_name (ascending)
    result = result.sort_values(
        by=['meeting_heavy_weeks', 'employee_name'], 
        ascending=[False, True]
    )
    
    # Return specific requested target columns
    return result[['employee_id', 'employee_name', 'department', 'meeting_heavy_weeks']]

```

### Line-by-Line Explanation

* **`pd.to_datetime(...)`**: Casts input data column objects into native pandas datetime formats to enable datetime processing properties.
* **`.dt.to_period('W-SUN')`**: Maps every individual explicit timestamp to an anchor group boundary closing on Sunday (running from Monday to Sunday), natively resolving week definitions.
* **`.groupby(['employee_id', 'week_id'])['duration_hours'].sum()`**: Groups dataframe entries by both employee tracking references and calculated week slots, then runs an additive sum on hours.
* **`weekly_hours[weekly_hours['duration_hours'] > 20]`**: Drops all index listings failing to meet the strict 20-hour minimum meeting condition.
* **`heavy_weeks.groupby('employee_id').size()`**: Tallies the total number of surviving rows (weeks) remaining for each distinct employee.
* **`pd.merge(..., how='inner')`**: Performs an inner-join match to construct a combined dataframe containing employee attributes alongside their overbooked week count metrics.
* **`.sort_values(..., ascending=[False, True])`**: Sorts rows by heavy weeks from highest to lowest, and resolves conflicts alphabetically.
