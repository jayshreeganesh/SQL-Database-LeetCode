# Find Students with Study Spiral Pattern: Multi-Language Blueprint

## Core Architectural Strategy

The problem requires discovering an exact, back-to-back repeating sequence of at least 3 subjects (cycle block lengths $N = 3, 4, \text{ or } 5$) completing at least 2 full cycles ($2N$ sessions total). Concurrently, a strict continuous constraint states that **no gap greater than 2 days** can exist between any consecutive study sessions across the student's entire timeline.

To achieve maximum efficiency and clean parsing across every engine, we avoid unstable recursions or correlated structural self-joins. Instead, we implement a **linear lookahead vector model** using window functions (`LEAD`), calculating structural row symmetry side-by-side with global date validation gaps.

## 1. MySQL 8.0 Solution

### Production Code

```sql
WITH RankedSessions AS (
    SELECT 
        student_id,
        subject,
        session_date,
        hours_studied,
        ROW_NUMBER() OVER(PARTITION BY student_id ORDER BY session_date) AS rn,
        LEAD(subject, 1) OVER(PARTITION BY student_id ORDER BY session_date) AS sub1,
        LEAD(subject, 2) OVER(PARTITION BY student_id ORDER BY session_date) AS sub2,
        LEAD(subject, 3) OVER(PARTITION BY student_id ORDER BY session_date) AS sub3,
        LEAD(subject, 4) OVER(PARTITION BY student_id ORDER BY session_date) AS sub4,
        LEAD(subject, 5) OVER(PARTITION BY student_id ORDER BY session_date) AS sub5,
        LEAD(subject, 6) OVER(PARTITION BY student_id ORDER BY session_date) AS sub6,
        LEAD(subject, 7) OVER(PARTITION BY student_id ORDER BY session_date) AS sub7,
        LEAD(subject, 8) OVER(PARTITION BY student_id ORDER BY session_date) AS sub8,
        LEAD(subject, 9) OVER(PARTITION BY student_id ORDER BY session_date) AS sub9,
        DATEDIFF(
            LEAD(session_date) OVER(PARTITION BY student_id ORDER BY session_date), 
            session_date
        ) AS next_gap
    FROM study_sessions
),
DisqualifiedStudents AS (
    SELECT DISTINCT student_id 
    FROM RankedSessions 
    WHERE next_gap > 2
),
ValidPatterns AS (
    SELECT 
        student_id,
        MAX(
            CASE 
                WHEN subject = sub5 AND sub1 = sub6 AND sub2 = sub7 AND sub3 = sub8 AND sub4 = sub9 THEN 5
                WHEN subject = sub4 AND sub1 = sub5 AND sub2 = sub6 AND sub3 = sub7 THEN 4
                WHEN subject = sub3 AND sub1 = sub4 AND sub2 = sub5 THEN 3
                ELSE 0 
            END
        ) AS cycle_length
    FROM RankedSessions
    WHERE student_id NOT IN (SELECT student_id FROM DisqualifiedStudents)
    GROUP BY student_id
),
StudyMetrics AS (
    SELECT 
        student_id, 
        ROUND(SUM(hours_studied), 1) AS total_study_hours
    FROM study_sessions
    GROUP BY student_id
)
SELECT 
    v.student_id,
    s.student_name,
    s.major,
    v.cycle_length,
    m.total_study_hours
FROM ValidPatterns v
JOIN students s ON v.student_id = s.student_id
JOIN StudyMetrics m ON v.student_id = m.student_id
WHERE v.cycle_length >= 3
ORDER BY v.cycle_length DESC, m.total_study_hours DESC, v.student_id ASC;

```

### Line-by-Line Logic Walkthrough

* **Lines 1–19 (`RankedSessions`):** Projects an inline matrix. We pull forward 9 sequential subject values via `LEAD(subject, offset)` ordered by date per student. `DATEDIFF` compares the current row's date to the immediately following date.
* **Lines 20–24 (`DisqualifiedStudents`):** Scans the `next_gap` window lookahead. If any individual day gap strictly exceeds 2 days anywhere in a student's logs, their ID is flagged for hard exclusion.
* **Lines 25–40 (`ValidPatterns`):** Aggregates pattern sequences per student. Using structural vector mapping:
* For $N=5$, the sequence at rows $[0..4]$ must explicitly equal slots $[5..9]$.
* For $N=4$, rows $[0..3]$ must equal $[4..7]$.
* For $N=3$, rows $[0..2]$ must equal $[3..5]$.
* `MAX()` safely bubbles up the largest matching cycle code block per student, discarding rows where the criteria isn't met.


* **Lines 41–47 (`StudyMetrics`):** Isolates complete sum aggregates of the core study window to guarantee exact rounding behavior prior to joining.
* **Lines 48–57 (`SELECT` Join):** Performs standard relational reduction via inner joins against the master registry (`students`). Discards non-matches (`cycle_length >= 3`), applying descending lexicographical sorting constraints.

## 2. Microsoft SQL Server 2019 Solution

### Production Code

```sql
WITH RankedSessions AS (
    SELECT 
        student_id,
        subject,
        session_date,
        hours_studied,
        LEAD(subject, 1) OVER(PARTITION BY student_id ORDER BY session_date) AS sub1,
        LEAD(subject, 2) OVER(PARTITION BY student_id ORDER BY session_date) AS sub2,
        LEAD(subject, 3) OVER(PARTITION BY student_id ORDER BY session_date) AS sub3,
        LEAD(subject, 4) OVER(PARTITION BY student_id ORDER BY session_date) AS sub4,
        LEAD(subject, 5) OVER(PARTITION BY student_id ORDER BY session_date) AS sub5,
        LEAD(subject, 6) OVER(PARTITION BY student_id ORDER BY session_date) AS sub6,
        LEAD(subject, 7) OVER(PARTITION BY student_id ORDER BY session_date) AS sub7,
        LEAD(subject, 8) OVER(PARTITION BY student_id ORDER BY session_date) AS sub8,
        LEAD(subject, 9) OVER(PARTITION BY student_id ORDER BY session_date) AS sub9,
        DATEDIFF(
            day, 
            session_date, 
            LEAD(session_date, 1) OVER(PARTITION BY student_id ORDER BY session_date)
        ) AS next_gap
    FROM study_sessions
),
ValidPatterns AS (
    SELECT 
        student_id,
        MAX(
            CASE 
                WHEN subject = sub5 AND sub1 = sub6 AND sub2 = sub7 AND sub3 = sub8 AND sub4 = sub9 THEN 5
                WHEN subject = sub4 AND sub1 = sub5 AND sub2 = sub6 AND sub3 = sub7 THEN 4
                WHEN subject = sub3 AND sub1 = sub4 AND sub2 = sub5 THEN 3
                ELSE 0 
            END
        ) AS cycle_length
    FROM RankedSessions rs
    WHERE NOT EXISTS (
        SELECT 1 
        FROM RankedSessions check_gap 
        WHERE check_gap.student_id = rs.student_id AND check_gap.next_gap > 2
    )
    GROUP BY student_id
),
StudyMetrics AS (
    SELECT 
        student_id, 
        CAST(ROUND(SUM(hours_studied), 1) AS DECIMAL(10,1)) AS total_study_hours
    FROM study_sessions
    GROUP BY student_id
)
SELECT 
    v.student_id,
    s.student_name,
    s.major,
    v.cycle_length,
    m.total_study_hours
FROM ValidPatterns v
INNER JOIN students s ON v.student_id = s.student_id
INNER JOIN StudyMetrics m ON v.student_id = m.student_id
WHERE v.cycle_length >= 3
ORDER BY v.cycle_length DESC, m.total_study_hours DESC, v.student_id ASC;

```

### Line-by-Line Logic Walkthrough

* **Lines 1–19 (`RankedSessions`):** Establishes window arrays. T-SQL requires explicit unit declarations for its datetime evaluations; hence `DATEDIFF(day, start, end)` is utilized to map row-to-row day offsets.
* **Lines 20–37 (`ValidPatterns`):** Uses an optimized `NOT EXISTS` correlated semi-join subquery to filter student timelines. If a student records any record breaking the 2-day contiguous step constraint, their group rows fail inclusion immediately.
* **Lines 31–35 (`CASE` Resolution):** Cascades down the scalar matching layers. By prioritizing 5 first, shorter sub-matches (like a pattern matching $N=3$ inside an active $N=5$ stream) are naturally overridden by the true maximum period window.
* **Lines 38–44 (`StudyMetrics`):** Evaluates total active duration weights. Explicit typing casting to `DECIMAL(10,1)` shields aggregate outputs from engine trailing zero padding configurations.
* **Lines 45–54 (`SELECT` Output):** Performs standard final relational joins and enforces structural sorting hierarchies.

## 3. PostgreSQL 16 Solution

### Production Code

```sql
WITH RankedSessions AS (
    SELECT 
        student_id,
        subject,
        session_date,
        hours_studied,
        LEAD(subject, 1) OVER w AS sub1,
        LEAD(subject, 2) OVER w AS sub2,
        LEAD(subject, 3) OVER w AS sub3,
        LEAD(subject, 4) OVER w AS sub4,
        LEAD(subject, 5) OVER w AS sub5,
        LEAD(subject, 6) OVER w AS sub6,
        LEAD(subject, 7) OVER w AS sub7,
        LEAD(subject, 8) OVER w AS sub8,
        LEAD(subject, 9) OVER w AS sub9,
        (LEAD(session_date, 1) OVER w) - session_date AS next_gap
    FROM study_sessions
    WINDOW w AS (PARTITION BY student_id ORDER BY session_date)
),
ValidPatterns AS (
    SELECT 
        student_id,
        MAX(
            CASE 
                WHEN subject = sub5 AND sub1 = sub6 AND sub2 = sub7 AND sub3 = sub8 AND sub4 = sub9 THEN 5
                WHEN subject = sub4 AND sub1 = sub5 AND sub2 = sub6 AND sub3 = sub7 THEN 4
                WHEN subject = sub3 AND sub1 = sub4 AND sub2 = sub5 THEN 3
                ELSE 0 
            END
        ) AS cycle_length
    FROM RankedSessions
    GROUP BY student_id
    HAVING NOT EXISTS (
        SELECT 1 
        FROM RankedSessions rs2 
        WHERE rs2.student_id = RankedSessions.student_id AND rs2.next_gap > 2
    )
),
StudyMetrics AS (
    SELECT 
        student_id, 
        ROUND(SUM(hours_studied)::numeric, 1) AS total_study_hours
    FROM study_sessions
    GROUP BY student_id
)
SELECT 
    v.student_id,
    s.student_name,
    s.major,
    v.cycle_length,
    v.total_study_hours
FROM (
    SELECT p.student_id, p.cycle_length, m.total_study_hours
    FROM ValidPatterns p
    JOIN StudyMetrics m ON p.student_id = m.student_id
    WHERE p.cycle_length >= 3
) v
JOIN students s ON v.student_id = s.student_id
ORDER BY v.cycle_length DESC, v.total_study_hours DESC, v.student_id ASC;

```

### Line-by-Line Logic Walkthrough

* **Lines 1–16 (`RankedSessions`):** Capitalizes on Postgres native explicit syntax reuse via a named `WINDOW w` token to minimize analytical redundant declarations. Native date arithmetic subtraction handles tracking day offsets directly.
* **Lines 17–33 (`ValidPatterns`):** Aggregates candidate structures. The filtering step checking for student disqualifications is placed directly inside an aggregated `HAVING NOT EXISTS` block, isolating row processing inside working memory.
* **Lines 34–40 (`StudyMetrics`):** Casts structural sum floating values to native numerical schemas `::numeric` before rounding to maintain strict compliance with data type boundaries.
* **Lines 41–53 (`SELECT` Final Stage):** Joins datasets via a compiled execution subtree structure to filter non-matching elements early and preserve index pathways during sorting.

## 5. Python Pandas (3.10) Solution

### Production Code

```python
import pandas as pd
import numpy as np

def find_study_spiral_pattern(students: pd.DataFrame, study_sessions: pd.DataFrame) -> pd.DataFrame:
    # 1. Sort sessions chronologically for each student
    df = study_sessions.sort_values(by=['student_id', 'session_date']).copy()
    df['session_date'] = pd.to_datetime(df['session_date'])
    
    # 2. Check for any day gaps greater than 2 days to disqualify students entirely
    df['next_gap'] = df.groupby('student_id')['session_date'].diff(periods=-1).dt.days.abs()
    disqualified_ids = df[df['next_gap'] > 2]['student_id'].unique()
    
    # Filter down to only qualified students with contiguous study streaks
    valid_df = df[~df['student_id'].isin(disqualified_ids)].copy()
    
    # Track the maximum cycle length found per student
    student_cycles = {}
    
    # 3. Use lookahead shifts to verify structural patterns (N = 5 down to 3)
    for n in [5, 4, 3]:
        # Perform lookahead shifts inside each student partition group
        shifted_matches = []
        for i in range(n):
            current_sub = valid_df.groupby('student_id')['subject'].shift(-i)
            lookahead_sub = valid_df.groupby('student_id')['subject'].shift(-(i + n))
            # Match elements across the two cycle windows (i matches i+n)
            shifted_matches.append(current_sub == lookahead_sub)
            
        # All positions within the 2N block must perfectly align
        is_pattern_match = np.all(shifted_matches, axis=0)
        matched_student_ids = valid_df[is_pattern_match]['student_id'].unique()
        
        # Save the maximum cycle length found per student
        for s_id in matched_student_ids:
            if s_id not in student_cycles:
                student_cycles[s_id] = n
                
    # Convert the cycle tracking map to a DataFrame
    if not student_cycles:
        return pd.DataFrame(columns=['student_id', 'student_name', 'major', 'cycle_length', 'total_study_hours'])
        
    patterns_df = pd.DataFrame(list(student_cycles.items()), columns=['student_id', 'cycle_length'])
    
    # 4. Calculate overall study metrics for the matched group
    metrics = study_sessions.groupby('student_id')['hours_studied'].sum().round(1).reset_index(name='total_study_hours')
    
    # 5. Merge profile fields and enforce final sorting priorities
    result = (
        patterns_df
        .merge(students, on='student_id', how='inner')
        .merge(metrics, on='student_id', how='inner')
    )
    
    # Format and order columns to match the output schema
    result = result[['student_id', 'student_name', 'major', 'cycle_length', 'total_study_hours']]
    result = result.sort_values(
        by=['cycle_length', 'total_study_hours', 'student_id'], 
        ascending=[False, False, True]
    ).reset_index(drop=True)
    
    return result

```

### Line-by-Line Logic Walkthrough

* **Lines 5–7:** Enforces timeline ordering across student records. Explicit string casting to `pd.to_datetime` ensures safe date calculation intervals during subsequent analysis steps.
* **Lines 10–14:** Evaluates consecutive row date intervals using a negative step parameter lookahead (`periods=-1`). If any record exceeds the strict 2-day contiguous step constraint, their unique keys are appended to `disqualified_ids` and filtered out.
* **Lines 17–36 (`Vector Validation Loop`):** Validates pattern sequences downward from $N=5 \rightarrow 3$:
* Constructs parallel boolean series blocks testing if the category at position index $i$ accurately corresponds to position $i + N$.
* `np.all(..., axis=0)` compresses matrix observations across rows to ensure perfect alignment for the entire block window.
* Identified matches drop directly into `student_cycles`, where conditional safeguards (`if s_id not in student_cycles`) protect and preserve the highest valid pattern scale found.


* **Lines 39–45:** Creates dataframes tracking identified pattern results. Evaluates full cumulative duration summaries using `groupby` aggregations rounded off cleanly to 1 decimal place.
* **Lines 47–59:** Standardizes and transforms resulting output columns. Merges underlying target information matrices together while applying the required sorting criteria to the final dataset.
