
# Find Golden Hour Customers - Comprehensive Multi-Language Solutions

This document provides fully validated, optimized solutions for LeetCode 3705 ("Find Golden Hour Customers") across 5 major SQL/Data platforms. 

### The Core Problem Nuance
The problem requires identifying high-value customers based on peak-hour order concentrations. The primary trap is the strict time window: **11:00 to 14:00** and **18:00 to 21:00**. 
* Using basic hour extraction (e.g., `HOUR(timestamp) <= 14`) incorrectly matches up to `14:59:59`. 
* To pass all test cases, boundary checks must use a explicit timestamp/time format comparison up to exactly `14:00:00` and `21:00:00`.
* The `peak_hour_percentage` must be rounded to the nearest integer.

## 1. MySQL 8.0

### Solution
```sql
SELECT 
    customer_id,
    COUNT(order_id) AS total_orders,
    ROUND(100 * SUM(CASE WHEN TIME(order_timestamp) BETWEEN '11:00:00' AND '14:00:00' 
                           OR TIME(order_timestamp) BETWEEN '18:00:00' AND '21:00:00' 
                      THEN 1 ELSE 0 END) / COUNT(order_id), 0) AS peak_hour_percentage,
    ROUND(AVG(order_rating), 2) AS average_rating
FROM 
    restaurant_orders
GROUP BY 
    customer_id
HAVING 
    COUNT(order_id) >= 3
    AND SUM(CASE WHEN TIME(order_timestamp) BETWEEN '11:00:00' AND '14:00:00' 
                   OR TIME(order_timestamp) BETWEEN '18:00:00' AND '21:00:00' 
              THEN 1 ELSE 0 END) / COUNT(order_id) >= 0.60
    AND COUNT(order_rating) / COUNT(order_id) >= 0.50
    AND AVG(order_rating) >= 4.0
ORDER BY 
    average_rating DESC, 
    customer_id DESC;

```

### Line-by-Line Explanation

* **`SELECT customer_id`**: Identifies the specific customer group we are calculating metrics for.
* **`COUNT(order_id) AS total_orders`**: Counts every record within the customer's group to get their total order frequency.
* **`TIME(order_timestamp) BETWEEN '11:00:00' AND '14:00:00'`**: Isolates the time fragment out of the timestamp. `BETWEEN` is strictly inclusive, ensuring an order at exactly `14:00:00` counts, but `14:01:00` does not.
* **`SUM(CASE WHEN ... THEN 1 ELSE 0 END)`**: Accumulates a count of `1` for every order that lands squarely inside lunch or dinner peak hours.
* **`ROUND(100 * (...) / COUNT(order_id), 0)`**: Multiplies by 100 to change the fractional ratio into a percentage percentage format, rounding directly to the nearest whole integer.
* **`ROUND(AVG(order_rating), 2)`**: Computes the mean score of the non-null customer reviews, trimmed cleanly to 2 decimal places.
* **`HAVING COUNT(order_id) >= 3`**: Filters out users who haven't placed at least 3 orders.
* **`AND COUNT(order_rating) / COUNT(order_id) >= 0.50`**: Filters for users where at least 50% of total orders contain a valid rating (since `COUNT(order_rating)` skips `NULL` rows).
* **`ORDER BY average_rating DESC, customer_id DESC`**: Performs the final sorting layout as explicitly requested by the schema parameters.

## 2. Microsoft SQL Server 2019 (T-SQL)

### Solution

```sql
SELECT 
    customer_id,
    COUNT(order_id) AS total_orders,
    ROUND(100.0 * COUNT(CASE WHEN CAST(order_timestamp AS TIME) BETWEEN '11:00:00' AND '14:00:00' 
                               OR CAST(order_timestamp AS TIME) BETWEEN '18:00:00' AND '21:00:00' 
                          THEN 1 END) / COUNT(order_id), 0) AS peak_hour_percentage,
    ROUND(AVG(CAST(order_rating AS DECIMAL(5,2))), 2) AS average_rating
FROM 
    restaurant_orders
GROUP BY 
    customer_id
HAVING 
    COUNT(order_id) >= 3
    AND CAST(COUNT(CASE WHEN CAST(order_timestamp AS TIME) BETWEEN '11:00:00' AND '14:00:00' 
                          OR CAST(order_timestamp AS TIME) BETWEEN '18:00:00' AND '21:00:00' 
                     THEN 1 END) AS DECIMAL(5,2)) / COUNT(order_id) >= 0.60
    AND CAST(COUNT(order_rating) AS DECIMAL(5,2)) / COUNT(order_id) >= 0.50
    AND AVG(CAST(order_rating AS DECIMAL(5,2))) >= 4.0
ORDER BY 
    average_rating DESC, 
    customer_id DESC;

```

### Line-by-Line Explanation

* **`CAST(order_timestamp AS TIME)`**: Systematically strips away the calendar date parameters from the `DATETIME` field to expose a highly accurate `TIME` variable type.
* **`COUNT(CASE WHEN ... THEN 1 END)`**: Evaluates conditional targets. If conditions are missed, it implicitly returns `NULL`. Since T-SQL `COUNT()` ignores `NULL` entities, this accurately tracks only qualified peak events.
* **`100.0 * ...`**: Forces an implicit conversion to float/decimal math. T-SQL performs default integer division (e.g., `2 / 3 = 0`), so decimals are required to maintain ratios.
* **`CAST(order_rating AS DECIMAL(5,2))`**: Converts structural integer values inside the `AVG()` context to guarantee floating-point calculation returns highly distinct point values before final rounding rules are applied.

## 3. PostgreSQL 16

### Solution

```sql
SELECT 
    customer_id,
    COUNT(order_id) AS total_orders,
    ROUND(100.0 * COUNT(CASE WHEN order_timestamp::time BETWEEN '11:00:00' AND '14:00:00' 
                               OR order_timestamp::time BETWEEN '18:00:00' AND '21:00:00' 
                          THEN 1 END) / COUNT(order_id), 0) AS peak_hour_percentage,
    ROUND(AVG(order_rating), 2) AS average_rating
FROM 
    restaurant_orders
GROUP BY 
    customer_id
HAVING 
    COUNT(order_id) >= 3
    AND COUNT(CASE WHEN order_timestamp::time BETWEEN '11:00:00' AND '14:00:00' 
                     OR order_timestamp::time BETWEEN '18:00:00' AND '21:00:00' 
                THEN 1 END)::numeric / COUNT(order_id) >= 0.60
    AND COUNT(order_rating)::numeric / COUNT(order_id) >= 0.50
    AND AVG(order_rating) >= 4.0
ORDER BY 
    average_rating DESC, 
    customer_id DESC;

```

### Line-by-Line Explanation

* **`order_timestamp::time`**: Uses PostgreSQL's compact inline type casting shorthand (`::`) to instantaneously isolate the standard time track.
* **`::numeric`**: Converts raw counts to numeric values during division steps to completely prevent integer truncation issues.
* **`ROUND(..., 0)`**: Executes a reliable mathematical round to the absolute closest integer value.
* **`AVG(order_rating)`**: In PostgreSQL, calculating the average of integers natively returns an exact numeric category type, making it ready for immediate evaluation against the baseline requirement of `>= 4.0`.

## 5. Python 3.10 (Pandas 2.2.2 & NumPy 1.26.4)

### Solution

```python
import pandas as pd
import numpy as np
from datetime import time

def find_golden_hour_customers(restaurant_orders: pd.DataFrame) -> pd.DataFrame:
    # 1. Convert order_timestamp to datetime object series
    restaurant_orders['order_timestamp'] = pd.to_datetime(restaurant_orders['order_timestamp'])
    
    # 2. Extract the exact time component to avoid broader hour-integer bucket mistakes
    order_times = restaurant_orders['order_timestamp'].dt.time
    
    # 3. Create a strict time-based boolean mask checking standard boundaries
    is_peak_hour = (
        ((order_times >= time(11, 0, 0)) & (order_times <= time(14, 0, 0))) |
        ((order_times >= time(18, 0, 0)) & (order_times <= time(21, 0, 0)))
    )
    
    # 4. Group by customer_id and calculate the explicit summary aggregations
    grouped = restaurant_orders.groupby('customer_id').agg(
        total_orders=('order_id', 'count'),
        peak_orders=('order_timestamp', lambda x: is_peak_hour.loc[x.index].sum()),
        rated_orders=('order_rating', 'count'),
        average_rating=('order_rating', 'mean')
    ).reset_index()
    
    # 5. Calculate peak hour percentage and safely cast to whole integer
    grouped['peak_hour_percentage'] = (
        (grouped['peak_orders'] / grouped['total_orders']) * 100
    ).round(0).astype(int)
    
    # Round the average metrics down to two decimal spots
    grouped['average_rating'] = grouped['average_rating'].round(2)
    
    # 6. Construct the filtering evaluation mask (mimics the SQL HAVING block)
    mask = (
        (grouped['total_orders'] >= 3) &
        ((grouped['peak_orders'] / grouped['total_orders']) >= 0.60) &
        ((grouped['rated_orders'] / grouped['total_orders']) >= 0.50) &
        (grouped['average_rating'] >= 4.0)
    )
    
    result = grouped[mask][['customer_id', 'total_orders', 'peak_hour_percentage', 'average_rating']]
    
    # 7. Sort elements dynamically based on problem rules
    result = result.sort_values(
        by=['average_rating', 'customer_id'], 
        ascending=[False, False]
    ).reset_index(drop=True)
    
    return result

```

### Line-by-Line Explanation

* **`from datetime import time`**: Imports standard tracking components to enable explicit boundary checks down to the exact second.
* **`restaurant_orders['order_timestamp'].dt.time`**: Pulls an isolation layer directly from the object series vector, excluding calendar days.
* **`is_peak_hour.loc[x.index].sum()`**: Maps group records back onto our primary tracking boolean mask to find exactly how many rows are categorized within peak times.
* **`rated_orders=('order_rating', 'count')`**: Runs the standard Pandas count function, which omits missing values (`NaN`/`None`), matching SQL's native handling of missing values.
* **`grouped[mask][...]`**: Selects specific tracking series that clear all constraints simultaneously.
* **`sort_values(..., ascending=[False, False])`**: Organizes output ordering rules smoothly using dual-axis criteria matching.
