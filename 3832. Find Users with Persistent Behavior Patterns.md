
# Find Users with Persistent Behavior Patterns

## 1. MySQL 8.0
### Implementation
```sql
WITH UniqueUserActions AS (
    -- Step 1: Dedup parallel identical rows
    SELECT DISTINCT
        user_id,
        action_date,
        action
    FROM activity
),
StreakGroups AS (
    -- Step 2: Form continuous streak groups
    SELECT 
        user_id,
        action,
        action_date,
        DATE_SUB(action_date, INTERVAL ROW_NUMBER() OVER(
            PARTITION BY user_id, action 
            ORDER BY action_date
        ) DAY) AS streak_group
    FROM UniqueUserActions
),
StreakLengths AS (
    -- Step 3: Aggregate streak boundaries and lengths
    SELECT 
        user_id,
        action,
        COUNT(*) AS streak_length,
        MIN(action_date) AS start_date,
        MAX(action_date) AS end_date,
        ROW_NUMBER() OVER(
            PARTITION BY user_id 
            ORDER BY COUNT(*) DESC, MIN(action_date) ASC
        ) AS rn
    FROM StreakGroups
    GROUP BY user_id, action, streak_group
    HAVING COUNT(*) >= 5
)
-- Step 4: Extract the absolute longest streak per user
SELECT 
    user_id,
    action,
    streak_length,
    start_date,
    end_date
FROM StreakLengths
WHERE rn = 1
ORDER BY streak_length DESC, user_id ASC;

```

### Line-by-Line Explanation

* **`SELECT DISTINCT ...`**: Normalizes the initial log dataset. It prevents occurrences where a user does the same action multiple times a day from artificially inflating the streak counting mechanics.
* **`DATE_SUB(action_date, INTERVAL ROW_NUMBER() OVER(...) DAY)`**: This is the core logic. `ROW_NUMBER()` creates a monotonic sequence $(1, 2, 3...)$ within each specific `(user_id, action)` slice. Subtracting this sequence from the `action_date` keeps consecutive days anchored to the exact same relative starting target date string (`streak_group`).
* **`HAVING COUNT(*) >= 5`**: Discards short-lived activities that fail to sustain a minimum threshold duration of 5 days.
* **`ROW_NUMBER() OVER(PARTITION BY user_id ORDER BY COUNT(*) DESC, MIN(action_date) ASC)`**: Assigns rank sequences mapping specifically to user IDs. It prioritizes the highest volume counts (`streak_length`), breaking potential ties cleanly by finding the oldest (`MIN(action_date)`) streak first.
* **`WHERE rn = 1`**: Keeps only the row representing each user's maximum tracked behavioral pattern.

## 3. PostgreSQL 16

### Implementation

```sql

    SELECT DISTINCT
        user_id,
        action_date,
        action
    FROM activity

StreakGroups AS (

),
StreakLengths AS (
    SELECT 
        user_id,

        COUNT(*) AS streak_length,
        MIN(action_date) AS start_date,
        MAX(action_date) AS end_date,
        ROW_NUMBER() OVER(
            PARTITION BY user_id 
            ORDER BY COUNT(*) DESC, MIN(action_date) ASC
        ) AS rn
    FROM StreakGroups
    GROUP BY user_id, action, streak_group
    HAVING COUNT(*) >= 5
)
SELECT 
    user_id,
    action,
    streak_length,
    start_date,
    end_date
FROM StreakLengths
WHERE rn = 1
ORDER BY streak_length DESC, user_id ASC;

```

### Line-by-Line Explanation

* **`action_date - (ROW_NUMBER() OVER(...) * INTERVAL '1 day')`**: Postgres supports direct math operations on intervals. Multiplying the dynamic row sequence index directly by an explicitly typed `INTERVAL '1 day'` object seamlessly scales down the timeline for consecutive days to output the correct `streak_group`.

## 4. Oracle SQL 11.2

### Implementation

```sql
WITH UniqueUserActions AS (
    SELECT DISTINCT
        user_id,
        TRUNC(action_date) AS action_date,
        action
    FROM activity
),
StreakGroups AS (
    SELECT 
        user_id,
        action,
        action_date,
        (action_date - ROW_NUMBER() OVER(
            PARTITION BY user_id, action 
            ORDER BY action_date
        )) AS streak_group
    FROM UniqueUserActions
),
StreakLengths AS (
    SELECT 
        user_id,
        action,
        COUNT(*) AS streak_length,
        MIN(action_date) AS start_date,
        MAX(action_date) AS end_date,
        ROW_NUMBER() OVER(
            PARTITION BY user_id 
            ORDER BY COUNT(*) DESC, MIN(action_date) ASC
        ) AS rn
    FROM StreakGroups
    GROUP BY user_id, action, streak_group
    HAVING COUNT(*) >= 5
)
SELECT 
    user_id AS "user_id",
    action AS "action",
    streak_length AS "streak_length",
    TO_CHAR(start_date, 'YYYY-MM-DD') AS "start_date",
    TO_CHAR(end_date, 'YYYY-MM-DD') AS "end_date"
FROM StreakLengths
WHERE rn = 1
ORDER BY "streak_length" DESC, "user_id" ASC;

```

### Line-by-Line Explanation

* **`TRUNC(action_date)`**: Clears any potential hidden hours, minutes, or seconds from Oracle's legacy standard `DATE` format data types, standardizing comparisons at a pure day level.
* **`(action_date - ROW_NUMBER() OVER(...))`**: Oracle natively interprets regular integer subtraction on raw dates as an adjustment in whole days, removing the need for internal function wraps.
* **`TO_CHAR(..., 'YYYY-MM-DD')`**: Standardizes string evaluation patterns to match formatting engines used in verification frameworks, removing time fragments (`00:00:00`).
* **`user_id AS "user_id"`**: Uses exact double quotation wraps on all returned parameters. This forces the system to preserve requested lowercase formatting instead of auto-converting schemas into capital letters.

## 5. Python Pandas

### Implementation

```python
import pandas as pd

def find_behaviorally_stable_users(activity: pd.DataFrame) -> pd.DataFrame:
    # Step 1: Dedup parallel execution logs
    df = activity[['user_id', 'action_date', 'action']].drop_duplicates()
    
    # Standardize time elements to formal datetime instances
    df['action_date'] = pd.to_datetime(df['action_date'])
    
    # Step 2: Sort chronologically 
    df = df.sort_values(by=['user_id', 'action', 'action_date']).reset_index(drop=True)
    
    # Step 3: Map matching index sequences via cumcount
    seq = df.groupby(['user_id', 'action']).cumcount()
    df['streak_group'] = df['action_date'] - pd.to_timedelta(seq, unit='D')
    
    # Step 4: Run linear structural aggregation
    streaks = df.groupby(['user_id', 'action', 'streak_group']).agg(
        streak_length=('action_date', 'count'),
        start_date=('action_date', 'min'),
        end_date=('action_date', 'max')
    ).reset_index()
    
    # Drop rows that do not meet the minimum duration limit
    streaks = streaks[streaks['streak_length'] >= 5]
    
    if streaks.empty:
        return pd.DataFrame(columns=['user_id', 'action', 'streak_length', 'start_date', 'end_date'])
        
    # Step 5: Filter out trailing paths to only retain max records per unique profile
    streaks = streaks.sort_values(
        by=['streak_length', 'start_date'], 
        ascending=[False, True]
    )
    longest_streaks = streaks.drop_duplicates(subset=['user_id'], keep='first')
    
    # Re-apply string masks to cleanup final validation timelines
    longest_streaks['start_date'] = longest_streaks['start_date'].dt.strftime('%Y-%m-%d')
    longest_streaks['end_date'] = longest_streaks['end_date'].dt.strftime('%Y-%m-%d')
    
    # Format and present results
    result = longest_streaks[['user_id', 'action', 'streak_length', 'start_date', 'end_date']]
    result = result.sort_values(by=['streak_length', 'user_id'], ascending=[False, True])
    
    return result

```

### Line-by-Line Explanation

* **`drop_duplicates()`**: Drops identical daily logs, keeping matching chronological actions grouped clean at index initialization.
* **`sort_values(...)`**: Orders records sequentially so continuous active tracking calendars accurately line up against shifting index items.
* **`groupby(...).cumcount()`**: Mimics `ROW_NUMBER()`, mapping structured counters starting at 0 onto targeted groups.
* **`pd.to_timedelta(seq, unit='D')`**: Converts raw sequential integers into valid time structures, allowing them to be cleanly subtracted from `action_date` tracking objects.
* **`agg(streak_length=..., start_date=..., end_date=...)`**: Flattens vector ranges down into descriptive performance matrices detailing precise start boundaries and length maps.
* **`drop_duplicates(subset=['user_id'], keep='first')`**: Evaluates rows alongside pre-sorted priority filters, dropping shorter data overlaps while preserving each unique profile's longest record intact.
