
# Problem Analysis: Find Users with High Token Usage

### Requirements Breakdown
1. **Count Prompts**: Calculate total prompts submitted per user (`COUNT(prompt)`).
2. **Average Tokens**: Compute the average tokens per prompt, rounded to 2 decimal places (`ROUND(AVG(tokens), 2)`).
3. **Filter 1 (Threshold)**: Only include users who have submitted at least 3 prompts.
4. **Filter 2 (Anomaly/Spike)**: Only include users where at least one individual prompt has a token usage strictly **greater than** their own overall average token usage.
5. **Sorting**: Order by `avg_tokens` descending, then by `user_id` ascending.

---

## 1. MySQL 8.0

### Approach 1: The Optimized Aggregation Filter (Recommended)
This approach leverages mathematical logic: if a user has *at least one* prompt greater than their average, then their *maximum* prompt token count must be strictly greater than their average token count (`MAX(tokens) > AVG(tokens)`).

```sql
SELECT 
    user_id,
    COUNT(prompt) AS prompt_count,
    ROUND(AVG(tokens), 2) AS avg_tokens
FROM 
    prompts
GROUP BY 
    user_id
HAVING 
    COUNT(prompt) >= 3 
    AND MAX(tokens) > AVG(tokens)
ORDER BY 
    avg_tokens DESC, 
    user_id ASC;

```

#### Line-by-Line Explanation:

* **`SELECT user_id,`**: Retrieves the target user identifier.
* **`COUNT(prompt) AS prompt_count,`**: Counts the total number of entries per user and aliases it.
* **`ROUND(AVG(tokens), 2) AS avg_tokens`**: Computes the mean token size and rounds it cleanly to two decimal places.
* **`FROM prompts`**: Targets the core data table.
* **`GROUP BY user_id`**: Collapses rows so aggregate metrics can be calculated independently for every user.
* **`HAVING COUNT(prompt) >= 3`**: Filters out users who have less than 3 prompts.
* **`AND MAX(tokens) > AVG(tokens)`**: Verifies if the highest single token usage exceeds their calculated group average.
* **`ORDER BY avg_tokens DESC, user_id ASC;`**: Sorts by highest average tokens first, resolving ties numerically by user ID.

### Approach 2: Explicit Window Function (Alternative)

This approach explicitly calculates each user's average alongside raw data entries before applying filters via a Common Table Expression (CTE).

```sql
WITH UserStats AS (
    SELECT 
        user_id,
        prompt,
        tokens,
        COUNT(*) OVER(PARTITION BY user_id) as prompt_count,
        AVG(tokens) OVER(PARTITION BY user_id) as raw_avg
    FROM prompts
)
SELECT 
    user_id,
    prompt_count,
    ROUND(raw_avg, 2) AS avg_tokens
FROM UserStats
WHERE tokens > raw_avg AND prompt_count >= 3
GROUP BY user_id, prompt_count, raw_avg
ORDER BY avg_tokens DESC, user_id ASC;

```

## 2. MS SQL Server 2019

### Approach 1: The Group By Filter (Handling Integer Division)

In SQL Server, running `AVG()` on integer columns truncates decimals (integer division). We must cast `tokens` to float to protect precision.

```sql
SELECT 
    user_id,
    COUNT(prompt) AS prompt_count,
    ROUND(AVG(CAST(tokens AS FLOAT)), 2) AS avg_tokens
FROM 
    prompts
GROUP BY 
    user_id
HAVING 
    COUNT(prompt) >= 3 
    AND MAX(tokens) > AVG(CAST(tokens AS FLOAT))
ORDER BY 
    avg_tokens DESC, 
    user_id ASC;

```

#### Line-by-Line Explanation:

* **`ROUND(AVG(CAST(tokens AS FLOAT)), 2) AS avg_tokens`**: Converts the integer token count into a precision float data type before running the mathematical mean, ensuring decimal accuracy prior to rounding.
* **`HAVING COUNT(prompt) >= 3`**: Assures that the sample footprint includes 3 or more entries.
* **`AND MAX(tokens) > AVG(CAST(tokens AS FLOAT))`**: Ensures the absolute maximum metric surpasses the float-calculated average.

### Approach 2: Windowed CTE Method

```sql
WITH PartitionedUsers AS (
    SELECT 
        user_id,
        tokens,
        COUNT(*) OVER(PARTITION BY user_id) AS prompt_count,
        AVG(CAST(tokens AS FLOAT)) OVER(PARTITION BY user_id) AS raw_avg
    FROM prompts
)
SELECT 
    user_id,
    prompt_count,
    ROUND(raw_avg, 2) AS avg_tokens
FROM PartitionedUsers
WHERE tokens > raw_avg AND prompt_count >= 3
GROUP BY user_id, prompt_count, raw_avg
ORDER BY avg_tokens DESC, user_id ASC;

```

### Approach 2: CTE Filter with DISTINCT ON

```sql
WITH ComputedAverages AS (
    SELECT 
        user_id,
        tokens,
        COUNT(*) OVER(PARTITION BY user_id) AS prompt_count,
        AVG(tokens) OVER(PARTITION BY user_id) AS raw_avg
    FROM prompts
)
SELECT DISTINCT ON (user_id)
    user_id,
    prompt_count,
    ROUND(raw_avg, 2) AS avg_tokens
FROM ComputedAverages
WHERE prompt_count >= 3 AND tokens > raw_avg
ORDER BY user_id, avg_tokens DESC;

```

## 5. Python (Pandas 2.2.2 & NumPy 1.26.4)

### Approach 1: Vectorized Aggregation (Recommended)

This approach matches database execution patterns by computing column states simultaneously across high-performance memory blocks.

```python
import pandas as pd

def find_users_with_high_tokens(prompts: pd.DataFrame) -> pd.DataFrame:
    # 1. Group by user_id to compute structural metrics
    grouped = prompts.groupby('user_id').agg(
        prompt_count=('prompt', 'count'),
        avg_tokens=('tokens', 'mean'),
        max_tokens=('tokens', 'max')
    ).reset_index()
    
    # 2. Vectorized application of logic filtering conditions
    filtered = grouped[
        (grouped['prompt_count'] >= 3) & 
        (grouped['max_tokens'] > grouped['avg_tokens'])
    ].copy()
    
    # 3. Apply exact floating rounding constraint
    filtered['avg_tokens'] = filtered['avg_tokens'].round(2)
    
    # 4. Filter target columns and organize data matrix sorting positions
    result = filtered[['user_id', 'prompt_count', 'avg_tokens']].sort_values(
        by=['avg_tokens', 'user_id'], 
        ascending=[False, True]
    )
    
    return result

```

#### Line-by-Line Explanation:

* **`prompts.groupby('user_id').agg(...)`**: Clusters row entities contextually by user ID.
* **`prompt_count=('prompt', 'count')`**: Tallies the absolute string input records.
* **`avg_tokens=('tokens', 'mean')`**: Computes standard arithmetic array averages.
* **`max_tokens=('tokens', 'max')`**: Retains peak integer bounds.
* **`.reset_index()`**: flattens hierarchical index paths into flat data structures.
* **`filtered = grouped[...]`**: Eliminates users that do not meet the minimum prompt count or variance criteria.
* **`filtered['avg_tokens'].round(2)`**: Formats numbers to 2 decimal places.
* **`sort_values(by=[...], ascending=[False, True])`**: Arranges the rows by `avg_tokens` (descending) and `user_id` (ascending).

### Approach 2: Transform Mapping Mask

An alternative approach using Pandas `.transform()` to broadcast grouped values back to original dataframe index dimensions.

```python
import pandas as pd

def find_users_with_high_tokens_transform(prompts: pd.DataFrame) -> pd.DataFrame:
    # Broadcast group metrics to match original dimensions
    prompts['user_avg'] = prompts.groupby('user_id')['tokens'].transform('mean')
    prompts['user_count'] = prompts.groupby('user_id')['prompt'].transform('count')
    
    # Identify individual rows that breach the group average
    prompts['is_higher'] = prompts['tokens'] > prompts['user_avg']
    valid_users = prompts.groupby('user_id').filter(
        lambda x: (x['user_count'].iloc[0] >= 3) and (x['is_higher'].any())
    )
    
    # Structure the unique final schema output
    result = valid_users.groupby('user_id').agg(
        prompt_count=('prompt', 'count'),
        avg_tokens=('tokens', 'mean')
    ).reset_index()
    
    result['avg_tokens'] = result['avg_tokens'].round(2)
    return result.sort_values(by=['avg_tokens', 'user_id'], ascending=[False, True])
