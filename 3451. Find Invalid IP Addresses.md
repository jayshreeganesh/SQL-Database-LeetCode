# LeetCode 3451: Find Invalid IP Addresses (Multi-Language Solutions)

This document contains the optimized, accepted solutions for LeetCode 3451 across different SQL dialects and Pandas. The objective is to identify structurally or logically invalid IPv4 addresses, count their occurrences, and order them by `invalid_count` descending, then by `ip` descending.

---

## 1. MySQL

This approach leverages a strict, pure regular expression to validate a correct IPv4 octet configuration ($0-255$ with no leading zeros). We invert the match using `NOT REGEXP` to safely capture only the invalid entries.

```sql
SELECT 
    ip, 
    COUNT(*) AS invalid_count
FROM 
    logs
WHERE 
    ip NOT REGEXP '^(([0-9]|[1-9][0-9]|1[0-9]{2}|2[0-4][0-9]|25[0-5])\\.){3}([0-9]|[1-9][0-9]|1[0-9]{2}|2[0-4][0-9]|25[0-5])$'
GROUP BY 
    ip
ORDER BY 
    invalid_count DESC, 
    ip DESC;

```

## 2. MS SQL Server (T-SQL)

Because T-SQL's native `LIKE` operator does not support advanced regular expression quantifiers or alternations, we use `PARSENAME` to cleanly extract individual octets alongside structural string validations.

```sql
SELECT 
    ip, 
    COUNT(*) AS invalid_count
FROM 
    logs
WHERE 
    -- 1. Ensure it contains exactly 3 periods
    LEN(ip) - LEN(REPLACE(ip, '.', '')) <> 3
    
    -- 2. Ensure it contains only numbers and periods
    OR ip LIKE '%[^0-9.]%'
    
    -- 3. Check for illegal leading zeros (e.g., '01', but single '0' is allowed)
    OR PARSENAME(ip, 4) LIKE '0[0-9]%'
    OR PARSENAME(ip, 3) LIKE '0[0-9]%'
    OR PARSENAME(ip, 2) LIKE '0[0-9]%'
    OR PARSENAME(ip, 1) LIKE '0[0-9]%'
    
    -- 4. Check if any octet falls outside the 0-255 range
    OR CAST(PARSENAME(ip, 4) AS INT) NOT BETWEEN 0 AND 255
    OR CAST(PARSENAME(ip, 3) AS INT) NOT BETWEEN 0 AND 255
    OR CAST(PARSENAME(ip, 2) AS INT) NOT BETWEEN 0 AND 255
    OR CAST(PARSENAME(ip, 1) AS INT) NOT BETWEEN 0 AND 255
GROUP BY 
    ip
ORDER BY 
    invalid_count DESC, 
    ip DESC;

```

## 3. PostgreSQL

PostgreSQL provides flexible regular expression matching via the `!~` (POSIX does not match) operator. It cleanly validates the boundaries of each octet group.

```sql
SELECT 
    ip, 
    COUNT(*) AS invalid_count
FROM 
    logs
WHERE 
    ip !~ '^(([0-9]|[1-9][0-9]|1[0-9]{2}|2[0-4][0-9]|25[0-5])\.){3}([0-9]|[1-9][0-9]|1[0-9]{2}|2[0-4][0-9]|25[0-5])$'
GROUP BY 
    ip
ORDER BY 
    invalid_count DESC, 
    ip DESC;

```

## 4. Oracle (PL/SQL)

Oracle evaluates pattern compliance using the built-in `REGEXP_LIKE` feature within a `NOT` wrapper to target the non-conforming entries.

```sql
SELECT 
    ip, 
    COUNT(*) AS invalid_count
FROM 
    logs
WHERE 
    NOT REGEXP_LIKE(ip, '^(([0-9]|[1-9][0-9]|1[0-9]{2}|2[0-4][0-9]|25[0-5])\.){3}([0-9]|[1-9][0-9]|1[0-9]{2}|2[0-4][0-9]|25[0-5])$')
GROUP BY 
    ip
ORDER BY 
    invalid_count DESC, 
    ip DESC;

```

## 5. Pandas

Using Python's vectorization capabilities, we map out an IPv4 structure layout and filter using the inverse boolean mask `~`.

```python
import pandas as pd

def find_invalid_ips(logs: pd.DataFrame) -> pd.DataFrame:
    # 1. Define the regex pattern for a VALID IPv4 address segment
    valid_octet = r"([0-9]|[1-9][0-9]|1[0-9]{2}|2[0-4][0-9]|25[0-5])"
    valid_ip_pattern = rf"^{valid_octet}\.{valid_octet}\.{valid_octet}\.{valid_octet}$"
    
    # 2. Filter rows where the IP does NOT match the valid pattern
    invalid_logs = logs[~logs['ip'].str.match(valid_ip_pattern, na=False)]
    
    # 3. Group by IP and aggregate the log frequencies
    result = (
        invalid_logs.groupby('ip')
        .size()
        .reset_index(name='invalid_count')
    )
    
    # 4. Sort execution: count descending, tie-breaker IP string descending
    result = result.sort_values(
        by=['invalid_count', 'ip'], 
        ascending=[False, False]
    )
    
    return result

```
