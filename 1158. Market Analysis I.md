# LeetCode 1158. Market Analysis I

## Problem Description
Write a solution to find for each user, the join date and the number of orders they made as a buyer in `2019`.

Return the result table with any order.

---

## 1. MySQL Solution

### Query
```sql
SELECT 
    u.user_id AS buyer_id, 
    u.join_date, 
    COUNT(o.order_id) AS orders_in_2019
FROM 
    Users u
LEFT JOIN 
    Orders o ON u.user_id = o.buyer_id AND YEAR(o.order_date) = 2019
GROUP BY 
    u.user_id, 
    u.join_date;

```

### Complexity

* **Time Complexity:** $O(N + M)$ where $N$ is the number of users and $M$ is the number of orders.
* **Space Complexity:** $O(N)$ for grouping and returning the user records.

```sql
    COUNT(o.order_id) AS orders_in_2019
FROM 
    Users u
LEFT JOIN 
    Orders o ON u.user_id = o.buyer_id AND EXTRACT(YEAR FROM o.order_date) = 2019

    u.user_id, 
    u.join_date;

```

### Key Takeaway

* Instead of the `YEAR()` macro function, PostgreSQL uses the ANSI-SQL standard `EXTRACT(YEAR FROM column_name)` to pull numeric date parts cleanly.

## 4. Oracle PL/SQL Solution

### Query

```sql
/* Write your PL/SQL query statement below */
SELECT 
    u.user_id AS "buyer_id", 
    TO_CHAR(u.join_date, 'YYYY-MM-DD') AS "join_date", 
    COUNT(o.order_id) AS "orders_in_2019"
FROM 
    Users u
LEFT JOIN 
    Orders o ON u.user_id = o.buyer_id AND EXTRACT(YEAR FROM o.order_date) = 2019
GROUP BY 
    u.user_id, 
    u.join_date
ORDER BY 
    u.user_id ASC;

```

### Key Takeaway

* Oracle automatically formats `DATE` objects with a time component (`00:00:00`). To pass the LeetCode schema verification, `TO_CHAR(..., 'YYYY-MM-DD')` must be used.
* Double quotes (`"column"`) are required to prevent Oracle from outputting identifiers in default uppercase (`BUYER_ID`).

## 5. Pandas Solution

### Code

```python
import pandas as pd

def market_analysis(users: pd.DataFrame, orders: pd.DataFrame, items: pd.DataFrame) -> pd.DataFrame:
    # 1. Filter orders to only include 2019 records
    orders_2019 = orders[pd.to_datetime(orders['order_date']).dt.year == 2019]
    
    # 2. Count the number of orders per buyer in 2019
    order_counts = orders_2019.groupby('buyer_id').size().reset_index(name='orders_in_2019')
    
    # 3. Rename 'user_id' to 'buyer_id' BEFORE merging to prevent duplicate column names
    users = users.rename(columns={'user_id': 'buyer_id'})
    
    # 4. Left join users with the order counts on 'buyer_id'
    result = pd.merge(users, order_counts, on='buyer_id', how='left')
    
    # 5. Fill NaN values with 0 and cast back to integer type
    result['orders_in_2019'] = result['orders_in_2019'].fillna(0).astype(int)
    
    # 6. Return only the required schema columns
    return result[['buyer_id', 'join_date', 'orders_in_2019']]

```

### Complexity

* **Time Complexity:** $O(N + M)$ where filtering and grouping the orders table takes linear time relative to its rows, and merging takes linear time relative to the sizes of both tables.
* **Space Complexity:** $O(N + M)$ to hold intermediate temporary DataFrames (`orders_2019`, `order_counts`, and `result`).
